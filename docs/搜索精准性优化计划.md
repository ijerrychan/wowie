## 第一阶段：文件搜索契约

- 引擎显式声明 session 内由宿主匹配排序，还是由后端匹配并保留顺序；默认保持已有行为。
- Everything / Windows Search 文件 session 采用后端匹配，原生查询如 `ext:pdf report` 不再被标题匹配误删。
- 首批、有限结果和后续分页遵循相同规则；root 的入口结果继续遵循正常匹配和 fallback 规则。
- 通过引擎能力表达，禁止以插件 ID 特判；同步协议说明。

## 第二阶段：可学习的排序

- 保留匹配层级硬边界，行为学习不能让模糊结果越过精确结果。
- 同层级采用文本质量和有界行为加分，类别及插件顺序用于综合分相同时决胜。
- 保留收藏、历史置顶及 fallback 的既有约束。
- 频次使用有界对数增长，近期性采用真正七天半衰；兼容现有历史格式。

验收：反复成功选择可以提升同层结果；七天和十四天后权重逐步减小而非清零；未来时间戳和极大计数安全；有限搜索结果与完整排序前缀一致。

## 第三阶段：评测和后续扩展

第一、二阶段通过后再独立实施，避免一次改变过多召回变量。

- 建立固定查询及期望结果的数据集，先覆盖精确、前缀、别名、模糊、中文、原生文件语法和跨来源查询。
- 真实查询需要人工标注，目标为 100～200 条；合成样本不能代替真实用户准确率。
- 记录首位命中率、Top-5 召回率、MRR 与 P95；性能数据与现有基准使用相同环境比较。
- 后续分批加入别名来源与可信度、多词匹配、拼音、查询前缀学习，以及空输入常用推荐。
- 语义召回最后评估；先确保词法与行为排序可以解释、可以回归。

## 帮助文档分类与 Steam 空列表解码回归（2026-11-07）
