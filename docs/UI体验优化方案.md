# UI 体验优化方案

日期：2026-11-08。规划与验收由主代理负责，具体实现交给 Luna。

## 第二轮：无边框搜索与动效简化

本轮根据用户最新反馈调整第一轮的搜索焦点边框方案：搜索区与窗口画布连续，不再使用独立内容面或四边描边，仅在展开结果时保留一条弱分隔线。设置表单输入仍保留必要的字段边界。

统一语言采用 [Fluent 2 布局基础](https://fluent2.microsoft.design/layout)与[功能性动效原则](https://fluent2.microsoft.design/motion)，结合启动器高频键盘交互进行精简，不要求模拟 Windows 原生控件。4px 间距尺度、语义配色、文字层级和圆角沿用共享 token；系统字体、逻辑尺寸和平台缩放承担设备差异。

| 场景 | 本轮规则 | 目的 |
| --- | --- | --- |
| 输入、结果更新、分类选中 | 即时反馈，不做逐行入场或选中滑移 | 连续输入和键盘浏览不等待动画 |
| 搜索图标切换 | 固定尺寸的短交叉淡化或直接替换 | 移除缩放收缩与弹出感 |
| 引擎入口与返回 | 布局直接到位，不横向滑动输入文字 | 保持输入阅读稳定 |
| 详情打开与关闭 | 列表、详情宽度直接到最终布局；仅可使用短透明度过渡 | 避免列表挤压、文字重排与面板漂移 |
| 设置分类切换、插件分类展开 | 直接切换，不先降低整页透明度或推移列表 | 避免人为闪屏与几何抖动 |
| 开关 | 保留短位置与颜色过渡 | 清楚表达离散状态变化 |
| 加载 | 沿用 180ms 延迟静态局部提示 | 不重新引入占位闪烁和循环动效 |
| 动画关闭 | 所有应用内状态立即到终态 | 不依赖动画完成才能交互或清理 |

跨平台边界：内容层共用主题、间距、语义焦点和动效规则；窗口外框、阴影、激活、系统快捷键等属于平台层。移除通用控件中独立写死的 Windows 风格焦点颜色。现有应用级动画开关继续有效，操作系统减少动态效果的自动同步作为平台能力另行接入，不能宣称本轮已经完成。macOS/Linux 的完整系统集成仍是后续工作，本轮只建立一致的内容设计规则与边界。

验收沿用已有浅深主题、紧凑态、窄窗口、字号行高和分数 DPI 的软件渲染用例；重点检查无边框搜索的层级、详情过渡中列表几何稳定、动画关闭后的即时终态，以及之前的加载与过期操作防护不退化。

本轮实现与验收已完成：搜索图标和输入文字在引擎切换前后使用同一位置；图标只保留 90ms 原位交叉淡化，设置开关保留 120ms 反馈，其他应用内布局变化直接到位。搜索只保留原有一条分隔线，设置切页延迟与详情关闭清理等待已移除。最新软件渲染布局测试通过（1 项，8.67 秒），包含开启动画时详情列首帧的真实像素边界回归；过期上下文动作测试、格式与差异检查通过。主代理已视检最新浅深启动器、加载提示和设置页快照；这些验证不等同于 macOS/Linux 系统集成或真实设备上的动态观感测试。

## 现状检查

项目是 Rust + Slint 桌面启动器，已有共享中性色、字体、圆角、动效和用户强调色。应继续完善这套设计，避免加入另一种互不协调的视觉语言。

检查范围：`ui/design-system.slint`、`ui/launcher.slint`（包括上下文菜单）、`ui/settings.slint`、`src/ui/lifecycle.rs`、`src/ui/search_coordinator.rs` 和 `src/ui/details.rs`。

主要发现：

- 颜色与字重已集中管理，但间距、按钮高度、文字与图标对齐仍有分散的局部定义，需要建立通用节奏并应用于三个窗口。
- 搜索加载条件仅覆盖非空引擎查询；条件一成立，结果列表和详情立即隐藏，并被整块加载提示替换。连续输入和短请求容易引起空白与闪屏。
- 动态详情未命中缓存时立即切换为加载详情，快速请求也会经过加载画面。
- 查询代次、详情代次、分页状态和软件渲染布局测试已经存在，可以复用；保留旧画面后必须同步约束操作，避免旧查询内容被误执行。

## 同类产品参考

- [Raycast 搜索栏](https://manual.raycast.com/search-bar)：统一顶部输入和下方结果的结构，提供紧凑模式。借鉴稳定的搜索入口与清楚的内容层级。
- [Raycast 列表组件](https://developers.raycast.com/api-reference/user-interface/list)：结果分组、辅助信息、详情和操作各有明确角色。延续项目现有分组和快捷操作。
- [Flow Launcher 主题定义](https://github.com/Flow-Launcher/docs/blob/main/how-to-create-a-theme.md)：搜索窗口的背景、结果样式与尺寸可集中调整。借鉴可配置、紧凑且一致的窗口密度。

上述资料用于提炼设计方向；180ms 加载阈值是本项目的实现选择，不是对竞品实现的断言。

## 设计与实现顺序

1. **统一视觉节奏**：补充必要的共享间距与控件高度 token；协调搜索框、分类筛选、分组标题、结果辅助文字、详情操作、底部提示和设置页的对齐。沿用现有浅深主题和强调色，使用克制边界与明确 hover/focus。
2. **搜索加载反馈**：查询立即进入 pending 状态，约 180ms 后仍未完成才显示局部提示；结果和详情不再被整块加载界面替换。反馈不夺取焦点，不额外改变窗口或列表几何；完成后立即收起。
3. **操作与时序正确性**：pending 期间保留内容仅供上下文连续，不允许执行旧结果、旧详情或旧上下文菜单动作。输入、清空和 Escape 继续有效。延迟回调必须校验查询代次与当前完成状态。
4. **详情与分页**：动态详情先清除其他项目的内容和动作，再延迟显示加载文案；快速完成不闪提示。分页反馈局限于当前列表，追加结果保留既有滚动与选择。
5. **验证与文档**：运行格式、编译及现有布局/状态测试；补充真实状态转换回归。可行时保存软件渲染快照检查浅深主题、加载与详情，不把软件渲染结果等同于真实 DWM/DPI 设备验收。

## 加载状态约定

| 状态 | 可见内容 | 操作 |
| --- | --- | --- |
| 当前查询已完成 | 当前查询结果或明确空状态 | 正常使用 |
| 新查询未完成且不足 180ms | 保留既有画面，无加载文案 | 输入/退出可用，旧内容动作禁用 |
| 新查询未完成且超过 180ms | 保留既有画面，局部加载提示 | 同上 |
| 查询被替换或清空 | 跟随新查询/紧凑模式 | 旧定时器不得更新界面 |
| 动态详情未完成 | 当前项目的稳定详情区域 | 不显示或执行另一项目的旧操作 |
| 分页未完成 | 当前结果与滚动位置保持 | 当前已就绪结果可正常操作 |

## 验收重点

- 浅色、深色；中英文；520px 最小宽度；用户字体/行高设置；紧凑模式；详情展开；动画关闭。
- 快速本地搜索没有加载闪屏，慢查询显示局部状态且输入不中断。
- 连续输入 A→B、清空、退回根搜索时，A 的定时器或结果不能覆盖 B。
- 查询 pending 时 Enter、鼠标点击、右键、详情按钮/链接、旧菜单回调都不能执行旧项。
- 零结果只在当前查询确实完成后显示。
- 分页不重置选中项和滚动位置；快速详情完成不短暂显示加载文案。
- 保留现有排名、分组、窗口尺寸配置、原生窗口边界及键盘工作流。

具体交付、测试证据与边界以更新后的 `UI设计规范.md` 和实现验收结果为准。
