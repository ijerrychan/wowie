# 构建与体积

## 常用命令

在仓库根目录执行，使用提交的 `Cargo.lock`：

以下命令按用途选择，不要求每次全部执行。测试范围遵循[必要测试流程](开发文档.md#必要测试流程)：已运行测试时无需再用相同配置重复 `cargo check`/debug 构建；Clippy 用于代码质量检查，release 构建用于生成发布产物。

```powershell
cargo check --all-targets --locked
cargo test --locked --quiet
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
cargo build --release --locked
```

发布程序位于 `target/release/wowie.exe`。不要把 `deps`、`build`、`.fingerprint`、增量缓存或整个 `target` 作为发布包；按部署需要单独附带 `plugins` 等运行时文件。

需要在构建前同步 Windows 设置目录时，使用 `pwsh -NoProfile -File tools/build.ps1 -UpdateWindowsSettings`；普通 Cargo 构建保持离线快照行为。上游版本、译文复用条件、只读检查和失败处理见[Windows 设置索引](Windows设置索引.md#构建前自动更新)。

本机开发统一使用宿主目标，不要交替添加 `--target x86_64-pc-windows-msvc`，否则 Cargo 会在 `target/debug` 和 `target/x86_64-pc-windows-msvc/debug` 中分别缓存产物。只有交叉编译或明确需要指定目标时使用 `--target`。临时设置 `RUSTFLAGS`、切换依赖 features、编译器或 profile 也会产生新版本的缓存。

## 配置取舍

- `release` 使用 `opt-level = "s"`、ThinLTO 和单 codegen unit，优先缩小 Rust 代码体积，仍允许循环向量化；ThinLTO 减少完整 LTO 的链接时间和内存开销，首次发布构建仍会较慢。保留全部现有渲染后端。
- 发布构建关闭调试信息并设置 `strip = "symbols"`。发布产物不用于符号调试，需要调试时使用开发构建。
- 开发与测试构建为宿主保留行号信息，关闭依赖的类型和变量调试信息；仍保留断言、溢出检查和默认 panic unwind 行为。需要检查本项目的局部变量时，可临时用 `cargo --config profile.dev.debug=2 build`；需要检查依赖时，另外临时将 `[profile.dev.package."*"]` 的 `debug` 改为 `2`，完成后恢复默认并清理临时产物。
- `.cargo/config.toml` 默认关闭增量编译，避免重复构建累积增量缓存；Cargo 仍复用未变化的依赖。代价是修改本项目后重新编译较慢。需要时可临时设置 `$env:CARGO_INCREMENTAL = '1'`，完成后用 `Remove-Item Env:CARGO_INCREMENTAL` 恢复默认。
- 保留 Windows 的 8 MiB 主线程栈设置；它是栈预留设置，不代表可执行文件额外增加 8 MiB。

参数语义见 [Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html) 和 [Cargo configuration](https://doc.rust-lang.org/cargo/reference/config.html)。体积优化对运行性能的影响需用项目的[性能基准](性能基准.md)衡量。

## 检查与清理 target

配置变更不会删除旧缓存。首次切换配置会新建一批产物，目录可能暂时增大；旧调试符号、旧 features 和编译器对应的产物仍需清理。Cargo 不为项目 `target` 提供固定大小上限，所以不能保证目录永不增长。

```powershell
# 默认只统计本仓库 target 各子目录的大小。
powershell -NoProfile -ExecutionPolicy Bypass -File tools/target-maintenance.ps1

# 预览旧增量缓存清理，包括宿主、交叉目标和自定义 profile。
powershell -NoProfile -ExecutionPolicy Bypass -File tools/target-maintenance.ps1 -CleanIncremental -WhatIf

# 停止 Cargo/rustc 和运行中的 Wowie 后，清理旧增量缓存。
powershell -NoProfile -ExecutionPolicy Bypass -File tools/target-maintenance.ps1 -CleanIncremental

# 清掉开发/测试产物（后续需要重新编译），保留 release。
cargo clean --profile dev

# 工具链、依赖 features 或构建配置变更后，需要彻底重建时执行。
cargo clean
```

清理脚本只处理本仓库的 `target`，拒绝包含 junction 或符号链接的目录树。它不处理外部 `CARGO_TARGET_DIR`，也不删除 `native-effects-*` 等手工备份；这类文件需按用途另外管理。不要在 Cargo 正在构建时清理缓存。

## 本机验证

2026-10-02，Windows x86_64 MSVC，Rust/Cargo 1.98.1：

- 调整前本地 `target` 约 13 GiB，其中 `debug` 为 10.36 GiB，旧增量缓存为 2.29 GiB；脚本 `-CleanIncremental -WhatIf` 已验证清理范围。
- 最终 `cargo build --release --locked --offline` 成功，`wowie.exe` 为 30,266,880 字节（28.86 MiB），相较原有本地产物 35,595,776 字节（33.95 MiB）减少约 15%。保留全部渲染器；原有产物并非严格同源码的体积基准。
- 本机完整 LTO 对照产物为 27.79 MiB、构建耗时 21 分 3 秒；最终 ThinLTO 为 28.86 MiB、13 分 40 秒。选择多约 1.07 MiB 的 ThinLTO，减少链接成本。两次构建的缓存状态不同，耗时仅作本机参考，不能作为严格性能基准。
- 验证后执行 `cargo clean --profile dev --target-dir C:\Users\User\Documents\Projects\wowie\target`，回收 12.6 GiB，`target` 最终为 7.10 GiB；发布程序和 `native-effects-*` 手工备份均保留。剩余 `release` 中包含不同优化参数的旧缓存，开发/测试产物将在下一次执行时按新配置重建。
- `cargo fmt --check` 和 PowerShell 脚本语法检查通过。
- 当时的 Clippy 和测试结果是后续验证前的历史记录；当前状态见下方重新验证。
