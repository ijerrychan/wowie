# 结果列表呈现

## 参考与目标

- [Spotlight 官方指南](https://support.apple.com/en-mk/guide/mac-help/mchlp1008/mac)将最相关的匹配放在前面，并支持按内容类型查找。Wowie 用独立的“最佳匹配”区突出原排名首选结果，不引入新的推断服务。
- [Raycast List.Section](https://developers.raycast.com/api-reference/user-interface/list)通过相关结果分组、标题和补充信息组织列表；[Root Search](https://manual.raycast.com/search-bar)保留统一搜索和按结果类型提供操作。Wowie 复用语义分类组织其余结果，同时保留统一搜索、分类筛选和已有上下文菜单。

目标是让用户先看到最可能需要的结果，再快速比较不同类型的命中，避免长段同类结果挤占首屏。入口触发词、内容类型和分组标题保持独立语义。

## 呈现规则

### 根搜索

输入查询后，使用核心排名中的首选实体结果作为“最佳匹配”，仅展示一次。网页或命令的兜底动作不能冒充有内容依据的最佳匹配。

其余结果按 `ResultCategory` 分组。组顺序按原排名中各类别首次出现的位置确定，组内保留原相对排名；每类先显示三项。查看更多使用现有分类筛选，显示该类别在本次搜索快照中的完整结果，不把“更多”伪装成可执行搜索结果。核心 Top-256 上限保持不变，计数不代表整个数据源的总匹配数。

分类筛选后显示该类型的完整快照，不再施加首屏分组数量限制。必要时单一类别也保留“全部”和具体类别筛选，保证键盘用户能进入完整列表并返回。

### 空查询与显式会话

根搜索空输入按收藏、搜索入口和其他建议组织，不显示“最佳匹配”。搜索入口仍由 `EnterSearchEngine` 表达，只在入口显示触发词。

显式进入文件、书签、窗口或插件会话后，保留该引擎原有的菜单、结果顺序和分页规则，不把 root 分组策略强加给引擎。

### “其他”分类的含义

UI 将显式 `Other` 与尚未识别的 `Unclassified` 都显示为“其他”，因此它不等于某一种固定来源，也不表示匹配分数低。

- 软件索引在合并后按实际启动目标分类：Shell 应用为应用，HTTP(S) 为网站，其余按已支持的扩展名判断；无法判断的文件类型落入其他。帮助文件 `.chm`、`.hlp` 属于文档，不按具体软件名判断。
- 插件可明确返回 `other`。内置天气、翻译内容和部分会话菜单使用该类别，因为它们不是应用、游戏或文件；宿主不会根据标题猜测并覆盖插件声明。
- 自定义快捷动作生成的打开网址、网页搜索、执行命令等结果统一归入命令；真正的引擎入口根据 `EnterSearchEngine` 动作也归入命令。普通网站、书签和应用启动结果保持原内容类别，不根据标题或“具有 Launch 动作”一律改类。

命令分类同时覆盖入口和带参数的执行结果。旧收藏快照若仍标记为其他／未分类，且结果及主启动动作都明确来自快捷命令来源，也按命令呈现；没有启动动作的空状态提示不适用此兼容。收藏本身不决定类别，决定因素是内容／动作语义。

2026-11-07 只读检查本机 v11 原始缓存，发现 `7-Zip Help` 与 `Application Verifier Help` 的目标都是 `.chm`；此前通用扩展名列表遗漏帮助文档，导致它们进入其他。此项修复为扩展名规则，不在分类器加入软件名或 ID 特例。原始缓存中的未分类字段不等于最终 UI 类别，恢复缓存后仍会经过合并和分类。

## 实现边界

- 核心匹配、排名、收藏和类别优先设置继续决定原始候选顺序。分组属于 UI 呈现阶段，不修改 `RankKey` 或 provider 的查询实现。
- 完整候选快照和实际显示快照分开保留；发布给执行层的结果顺序必须与显示行一致。选择恢复依靠稳定 ID，异步图标写回同时校验查询代次和行 ID。
- 分组标题只作为结果行的非选择性装饰，不生成虚假 `SearchResult`。上下键、Home/End、Enter 和上下文菜单始终指向真实结果。
- 保留 ListView 虚拟化。滚动位置和图标可见范围必须计入分组标题高度，不能继续直接用固定行高推算所有坐标。
- 列表总高度显式使用结果正文和分组标题的精确高度，避免虚拟列表按当前可见行估算导致末项无法进入视口。新查询回到顶部；分类切换或异步更新后，即使选中索引未变，也要重新确保选中项可见。
- 类型文字与触发词沿用独立字段。自带图标遵循 Iconify 资源规范。
- 计算范围限于现有有界快照；不增加磁盘扫描、网络请求、后台线程或第二套索引。
