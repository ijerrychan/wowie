# 搜索引擎架构

## 边界

`SearchEngineProvider` 是唯一的搜索来源抽象。root search 不再是一类
provider，而是 `ProviderRegistry` 对已注册引擎的聚合：只有
`SearchEngineSettings.participates_in_root = true` 的引擎会被调用。

搜索引擎可以完全没有 session，也不必生成“进入引擎”的自定义结果。比如
Calculator、应用索引和控制面板索引直接由 root 调用；它们仍然是独立引擎。
自定义结果只是可选的 session 入口，入口的 `EnterSearchEngine` action 和
引擎本身是两个独立概念。

## 统一设置

每个引擎通过 `SearchEngineProvider::settings()` 返回
`SearchEngineSettings`：

- `participates_in_root`：是否由 root search 聚合；不影响显式 session。
- `respect_global_fuzzy_search`：是否使用用户的 `fuzzy_search` 偏好。为 false
  时该引擎仍走统一的精确/子串匹配路径，只是不启用模糊匹配。
- `ranking_bias`：-100 至 100 的引擎级同分偏置；仅在匹配质量、使用历史和
  结果类别都相同后参与排序，不能用来压过更精确的匹配。

设置由引擎声明，而匹配和排序仍只在 `SearchCore` 执行；引擎不得复制匹配器
或修改结果标题来影响排序。插件在 `manifest.json` 的 `engine` 字段使用同一
结构；例如 `{"engine":{"participates_in_root":false,"respect_global_fuzzy_search":true,"ranking_bias":0}}`。
插件宿主会为每个插件保留该设置，而不是在 UI 或 root search 中增加插件 ID 判断。

## 内置引擎

- `IndexedSearchEngine(apps)` 与 `IndexedSearchEngine(control_panel)` 共享应用
  发现器发布的不可变索引快照，但拥有彼此独立的引擎边界。
- `CalculatorProvider` 是无 session 的引擎。
- `ShortcutProvider`、Everything 和插件可选择提供 session；其入口结果仍然是
  普通 `SearchResult`。

新增内置引擎放在 `src/providers/dynamic/` 并实现
`SearchEngineProvider`；`build.rs` 会自动注册它。不要重新引入
`DynamicProvider`，也不要把一个引擎是否存在绑定到自定义结果项。

## 空查询会话展示

自定义结果可声明 `ResultVisibility::EmptyQueryOnly`。它只在当前搜索引擎的输入为空时
参与候选和排序，开始输入后即被移除；结果本身仍是普通 `SearchResult`，因此可使用图标、
详情面板、`OpenDetail`、插件 action 和 session 菜单更新等全部能力。root search 的空输入
也只显示这类显式声明的结果，不会枚举应用、控制面板或文件索引。

引擎仍会在空查询时执行自己的 `query_active`：适合菜单型 session 直接返回菜单
项，例如翻译引擎的源语言和目标语言选择。若未返回空查询可见的结果，界面按普通
空结果处理并显示“无结果”。Everything 使用带 `OpenDetail` 的普通介绍结果，说明其
支持 Everything 的全部查询语法。

## Root 排序默认值

非空 root search 不按类别分组，而是将所有引擎候选混排。比较顺序固定为：

1. 普通匹配优先于 shortcut/web 等 fallback；
2. 匹配层级（精确、前缀、包含、模糊）；
3. 同一匹配的文本质量与该 query 的使用历史；
4. 类别默认偏置：Calculator、Application、ControlPanel、Game、Document、
   Other、Website；
5. 引擎偏置、结果偏置、标题和稳定 ID。

这让精确的网站或文件名不会因类别输给较弱的应用匹配，同时在同等结果中优先
常见的启动器操作。默认 Apps 为 +25、Control Panel 为 +15、Calculator 为 +40；
Everything 和未配置插件为 0，快捷方式/网页兜底继续以结果级 fallback 排在末尾。
