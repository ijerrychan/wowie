# 搜索引擎架构

## 边界

`SearchEngineProvider` 是唯一的搜索来源抽象。root search 不再是一类
provider，而是 `ProviderRegistry` 对已注册引擎的聚合：只有
`SearchEngineSettings.participates_in_root = true` 的引擎会被调用。

搜索引擎可以完全没有 session，也不必生成“进入引擎”的自定义结果。比如
Calculator、应用索引和控制面板索引直接由 root 调用；它们仍然是独立引擎。
自定义结果只是可选的 session 入口，入口的 `EnterSearchEngine` action 和
引擎本身是两个独立概念。

## 统一设置

每个引擎通过 `SearchEngineProvider::settings()` 返回
`SearchEngineSettings`：

- `participates_in_root`：是否由 root search 聚合；不影响显式 session。
- `respect_global_fuzzy_search`：是否使用用户的 `fuzzy_search` 偏好。为 false
  时该引擎仍走统一的精确/子串匹配路径，只是不启用模糊匹配。
- `ranking_bias`：-100 至 100 的引擎级同分偏置；仅在匹配质量、用户设置的
  类别/插件顺序和使用历史都相同后参与排序，不能用来压过更精确的匹配。
- `history_limit`：进入该引擎后成功执行的最近查询数量；设为 `0`（默认值）
  表示不记录。宿主最多保存 50 条，空查询时将记录交给引擎生成历史结果。
- `matching_policy`：`central`（默认）表示宿主统一匹配和排序；`provider_owned`
  表示该引擎的非空 session 查询由后端负责匹配与顺序。它不改变 root search，
  也不改变空查询中的收藏和查询历史规则。

默认情况下匹配和排序只在 `SearchCore` 执行；选择 `provider_owned` 的引擎则须
自行保证候选匹配与顺序稳定，且不能通过修改结果标题伪造匹配。插件在 `manifest.json` 的 `engine` 字段使用同一
结构；例如 `{"engine":{"participates_in_root":false,"respect_global_fuzzy_search":true,"ranking_bias":0,"history_limit":10,"matching_policy":"central"}}`。
插件宿主会为每个插件保留该设置，而不是在 UI 或 root search 中增加插件 ID 判断。

root 搜索显示偏好由用户配置文件控制，Windows 上配置文件位于 `%APPDATA%\wowie\config.json`，修改后支持热加载。`compact_search`（默认 `false`）在空输入时收起结果栏，隐藏操作提示；按 `↓` 或开始输入后展开并重新居中。`separate_launch_entries`（默认 `false`）为可见的备用启动入口生成独立结果，同时保留默认启动项；它与上下文菜单共用 `show_advanced_launch_entries` 筛选规则，关闭高级项时仍显示带不同参数的快捷方式，开启后显示其余不同启动行为。`result_order` 和 `plugin_order` 是由设置界面维护的有序 ID 列表，排在前面的类别或插件先显示：

```json
{
  "compact_search": true,
  "separate_launch_entries": true,
  "result_order": ["calculator", "application", "game", "website"],
  "plugin_order": ["google-translate"]
}
```

收藏和当前 session 的查询历史仍保持置顶。其余结果先比较文本匹配层级；同一层内将词法质量与最多 100 分的行为加成相加，再比较结果类别和插件顺序。旧版 `result_priorities` 数值会迁移为类别顺序，旧版插件权重会迁移为插件顺序。

收藏结果与成功查询历史共用本地 `history.json` 持久化；收藏保存完整结果及其 session 上下文快照，最多 256 项。
root search 空输入时把收藏作为推荐加入结果，App Provider 来源的收藏只在当前索引仍有该项时显示，避免已卸载应用通过收藏快照复活；其他收藏仅对当前引擎实际返回的匹配项置顶；
跨 session 的收藏不会被错误地注入到非空 root 查询。上下文菜单可对任意结果添加或移除收藏。
UI 以星标区分收藏。执行型 session 的非空 query 结果不可添加收藏；快捷命令/网址 session
的动态执行行使用 query-specific ID，避免与 root 中进入 session 的快捷项共用身份。

查询历史只在 session 中某个结果成功执行后写入现有的本地 `history.json`，按引擎隔离、
忽略大小写去重并将最近使用的条目排在前面。设置 `history_limit` 的 Rust 引擎可实现
`query_history()` 生成独立的可执行历史行；插件的空查询会在 query 请求中收到
`search_history` 数组（每项有原查询和稳定 `result_id`），由插件决定是否及如何展示。
切换引擎或配置不会把一个引擎的查询历史混入另一个引擎。

## 内置引擎

- `IndexedSearchEngine(apps)` 与 `IndexedSearchEngine(control_panel)` 共享应用
  发现器发布的不可变索引快照，但拥有彼此独立的引擎边界。
- `control_panel` 引擎也聚合 PowerToys 派生的 Windows 设置目录；设置页使用独立的
  `Settings` 结果分类，按官方 `ms-settings:` URI 启动，并以所有已发布语言的别名参与搜索。
  索引根据 Windows build 与可探测硬件能力过滤已知不适用的页面；缺少本机页面证据或无法确认所需硬件能力时不发布页面；同时检查 edition 和页面可见性策略。
  设置标题与目录路径按当前语言本地化，路径显示为结果副标题；打开高级详情后显示启动 URI。
  `Settings` 分类使用 Windows 设置应用图标；目录中的传统控制面板和 MMC 项继续使用
  `ControlPanel` 分类。
- `CalculatorProvider` 是无 session 的引擎。
- `ShortcutProvider` 与插件可选择提供 session；其入口结果仍然是普通 `SearchResult`。
- `FileSearchProvider` 是 `src/providers/dynamic/file_search.rs` 中的 Rust 内置引擎，默认通过
  `e ` 进入会话，不再分发或加载 Everything Lua 插件。它通过 `provider_owned` 声明由后端
  处理原生语法和顺序；首页与后续页遵从同一策略，root 入口仍由宿主统一匹配。
  `src/services/file_search.rs` 共享 Everything IPC 与 Windows Search 查询实现。自动模式优先
  Everything，不可用或查询失败时使用 Windows Search；后者只搜索已编入索引位置的文件名。

文件搜索设置位于搜索分类，对应 `file_search_enabled`（默认 `true`）、
`file_search_backend`（默认 `auto`，也可选 `everything` / `windows-index`）与
`file_search_keyword`（默认 `e`）。配置热更新直接更新运行时设置，并取消旧查询。
加载旧配置时迁移 `plugins.everything` 的开关、后端及首个自定义搜索关键词；显式的新字段
优先，旧插件配置与优先级项不再保留。兼容旧收藏所需的结果及 session ID，实际来源为内置文件搜索。
旧磁盘 Everything 插件不再重复加载，但不会自动删除用户目录中的文件。其他插件不受影响。

Windows Search session 使用 WinRT 异步查询，不设固定等待时限；等待期间每 10ms 检查一次取消状态。Everything IPC 等待上限为三秒，并每 10ms 检查取消。ProviderRegistry 通过共享代次取消查询，取消路径不等待正在查询的引擎互斥锁。普通插件保留自己的查询预算。

session 分页使用已显示行数作为下一页的 `offset`，宿主会按结果 ID 去重并应用可见性规则。因此声明 `provider_owned` 的后端应分页返回可见且 ID 唯一的结果；若页面中有结果被宿主过滤或去重，后端收到的后续 offset 可能小于其原始扫描行数。

新增内置引擎放在 `src/providers/dynamic/` 并实现
`SearchEngineProvider`；`build.rs` 会自动注册它。不要重新引入
`DynamicProvider`，也不要把一个引擎是否存在绑定到自定义结果项。

## 空查询会话展示

自定义结果可声明 `ResultVisibility::EmptyQueryOnly`。它只在当前搜索引擎的输入为空时
参与候选和排序，开始输入后即被移除；结果本身仍是普通 `SearchResult`，因此可使用图标、
详情面板、`OpenDetail`、插件 action 和 session 菜单更新等全部能力。谷歌翻译保留空输入
菜单结果；其他 session 的介绍信息通过空状态页面显示。root search 的空输入也只显示明确
声明的入口结果，不会枚举应用、控制面板或文件索引。

引擎仍会在空查询时执行自己的 `query_active`：适合菜单型 session 直接返回菜单
项，例如翻译引擎的源语言和目标语言选择。若搜索没有返回任何结果，
`SearchEngineProvider::empty_state()` 可选地返回一个 `SearchResult` 作为空状态
内容；插件可用 `empty_state` 回调提供相同内容。宿主仅使用它的图标、标题、描述和 `DetailView`：空状态固定在结果区域中央，
点击或按 Enter 可打开其详情；详情打开后空状态会隐藏。空状态不进入结果模型、不会
参与排序，也不需要创建专用 intro 结果类型。未提供时则显示通用“无结果”提示。
内置文件搜索通过空状态说明当前后端；Everything 可使用其完整查询语法，
Windows Search 后备按 Windows 文件索引搜索文件名。

## Root 排序默认值

中央匹配对查询和候选文本统一处理大小写、全角 ASCII（U+FF01–U+FF5E）、全角空格及连续空白；这是有限规范化，不是完整 Unicode NFKC。非空输入仍以原文交给 provider，避免改写命令、URL 或文件后端语法。root 的纯空白输入按空查询处理，不枚举应用索引。行为查询键采用同一规范化，加载历史时合并旧形式。

连续短语沿用精确、前缀、词首和包含规则；多词查询另支持非连续、倒序及跨标题/别名的 AND 匹配，所有词都必须有证据。路径和描述不参与此召回。跨字段命中不能提升为精确或前缀匹配；关闭模糊搜索后仍允许非模糊的多词覆盖。最佳匹配使用相同的证据判断，不因新增召回而降低其门槛。

标题获得有限的质量加分，可靠别名保留原有匹配层级。索引字段按来源分为名称（标题、可信别名）、关键词、上下文和技术标识。名称证据优先于辅助字段，行为分不能跨越此边界；辅助字段不能单独产生最佳匹配。

关键词只参与保守的词或短语匹配，不做模糊匹配。候选快照中高频关键词和纯数字关键词不能独立成为召回锚点，但可补全已有锚点的多词查询。上下文也只能辅助多词查询；技术标识只允许完整精确匹配。规则不依赖结果名称、类别或数字长度，真实数字名称及显式数字别名仍然有效。

Shell 关键词、设置目录分类、包身份、书签容器和 Steam appid 分别迁移到对应字段。打包应用另按 AUMID 的 Application Id 从包清单读取其独有的可执行文件名，补充可信名称别名；共用执行宿主不提升为名称，完整包身份仍为技术标识。该规则用于补齐本地化显示名的非本地化搜索来源，不提供任意语言翻译。

应用发现使用五个逻辑来源：统一应用来源（AppsFolder 为主、Package 补缺）、开始菜单、桌面、控制面板／设置、自定义目录。统一应用来源内部保留真实 SourceId 和启动证据，按身份合并两条发现渠道，包变更通知也进入同一刷新队列。来源精简不以显示名相同为删除依据。

真实 EXE 以及快捷方式解析到的 EXE 可在发现阶段读取 VERSIONINFO 的语言／代码页表，将 FileDescription 放入关键词、ProductName 放入上下文。该补充不覆盖显示标题，不把套件名当作等价名称，也不依赖公司名或版本号召回；读取有资源和条目上限，缓存随文件长度与修改时间变化，查询热路径不重新读取文件。

索引缓存升级为 v11，旧系统索引在下次加载时自然重建；历史结果缺失可选元数据时使用空默认值。旧插件的 aliases 仍按名称兼容读取，插件应主动迁移非名称字段。

核心 root search 将所有引擎候选混排；UI 可在有界快照上以“最佳匹配 + 分类分组”呈现，具体规则见[结果列表呈现](结果列表呈现.md)。分组不改变核心排名键。收藏结果在核心排序中始终置顶，并按最近加入顺序排列；
其余结果的比较顺序固定为：

1. 收藏与当前 session 的查询历史置顶；
2. 其他结果先按名称／辅助证据排序，再按匹配层级（精确、前缀、词首、包含、模糊）排序；同层将文本质量与有限行为加成合成后比较；
3. 普通匹配优先于 shortcut/web 等 fallback；
4. 用户设置的结果类别顺序和插件顺序；
5. 引擎偏置、结果偏置、标题和稳定 ID。

隐式快捷命令的动态标题包含当前输入，因此统一使用兜底匹配分数，避免生成的命令标题压过真实应用名称或别名匹配。显式进入 session 后继续使用该引擎的正常结果规则。

收藏和查询历史仍严格置顶，匹配层级仍是硬边界。同层行为分数可改变不同长度候选的顺序；
较大的行为分不能跨越精确、前缀、词首、包含或模糊层级。类别顺序只在合成分相同时决胜，
因此显著不同的学习分数可能排在用户偏好的类别之前。默认顺序为 Calculator、Application、Control Panel、
Game、Document、Other、Unclassified、Website；快捷方式/网页兜底继续排在普通匹配之后。

行为分数使用 7 天指数半衰，并将频率按最多 10,000 次启动做对数缩放；日期在未来时按刚刚使用处理。旧版 `history.json` 的启动计数和时间戳格式保持兼容。所有候选都使用一致的排序键，避免混合来源时产生相互矛盾的比较结果；一次搜索共用同一份加锁历史和时间戳。
