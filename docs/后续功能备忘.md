# 性能基线与后续功能备忘

记录 2026-11-05 的启动器搜索基线优化和后续产品功能顺序。此文档用于分阶段规划，不代表后续功能已经实现。

## 本次基线优化

- UI 首屏仍为所有候选打分，确保匹配、收藏、分类和 provider 顺序保持一致；排名后使用部分选择，仅保留 UI 上限 256 条，再排序和复制结果。无界的 `search_in_context` API 保留原有行为。
- 匹配过程复用小写转换缓冲；ASCII 字段在关闭模糊搜索且精确、前缀和包含匹配均未命中时直接返回，跳过不必要的大小写转换。
- 这次没有改变文件搜索后端，也不引入自建索引。现有 Everything IPC 与 Windows Search 后备保持不变。

## 性能与内存验证待办

- `性能基准.md` 中的 10,000 项搜索数据是 2026-09-29 的 Windows debug 基准：连续查询 P50/P95 为 202.7/295.0 ms。该历史基准通过无界搜索 API，不衡量本次 UI 有界排名路径；本次未运行基准，因此没有声称新的耗时数字或改善比例。
- 下一次性能评估应增加 UI 首屏有界搜索的同机前后对照，并保留无界 API 基准；同时记录候选数、匹配数和 P50/P95。发布版数据需单独测量，不能与 debug 基准混用。
- 现有图标缓存、插件结果、后台任务队列、历史记录和 UI 行数都有各自上限，但目前没有全进程工作集、私有字节或堆峰值基线。后续在冷启动、索引完成、连续搜索和图标加载后记录这些指标，再决定是否需要进一步压低缓存或改索引表示。
- 仍需对所有候选执行匹配，当前搜索耗时仍随候选数量增长。只有基准确认匹配阶段占主要成本后，再评估来源侧候选检索或增量索引；不要仅凭合成数字增加常驻倒排/ngram 数据。

## 后续功能顺序

1. **浏览器书签搜索**：先支持常见浏览器的只读书签发现、搜索与打开；明确多配置文件选择，并避免写入浏览器数据库。是否扩展到浏览历史另行决定。
2. **窗口切换**：按窗口标题和所属进程搜索当前可见窗口，并提供切换到窗口的操作。关闭窗口可作为显式次级操作；结束进程不作为默认动作。
3. **系统工具组**：补充锁屏、睡眠、重启等可确认的系统操作，以及单位转换、日期时间、GUID、哈希和 Base64 等轻量工具。能通过现有 provider/plugin 接口实现的功能优先用该接口接入。
4. **文件工作流补强**：在现有 Everything / Windows Search 结果上增加类型、日期或大小筛选、预览和 Explorer / 文件对话框快速切换。此项不包括新建本地文件索引。
5. **插件发现与更新**：评估插件目录、安装和更新流程，并清晰展示插件权限与来源；等前述高频搜索功能稳定后再排期。

## 分阶段实施计划

每阶段由 Luna 子代理编写代码，主代理负责边界设计、差异审查和验证；完成一个阶段再进入下一个阶段，提交信息沿用仓库的 `type(scope): 中文说明` 格式。

| 阶段 | 可交付范围 | 验收重点 |
| --- | --- | --- |
| 1：浏览器书签 | Windows Chrome / Edge 的多配置文件书签发现、名称/文件夹搜索和默认浏览器打开 | 只读、有界解析；搜索按键不触发同步磁盘扫描；支持损坏文件与无浏览器环境；稳定身份与重复记录处理 |
| 2：窗口切换 | 当前用户可见窗口的标题/进程搜索与前台切换 | 排除启动器自身及无效窗口；窗口关闭后的失效处理；不把结束进程作为默认动作 |
| 3：系统工具 | 先补锁屏和轻量日期/单位转换，再扩展需要确认的睡眠、重启等操作 | 通过现有 Action/Provider 接入；危险操作明确确认；工具结果便于复制；不阻塞 root search |
| 4：文件工作流 | 基于现有后端完善筛选、预览和目录切换 | 保持 Everything / Windows Search 后端；媒体读取有预算与取消 |
| 5：插件管理 | 目录发现、安装更新与来源/权限展示 | 独立评估分发协议和更新回滚后再实施 |

第一阶段先支持 Chromium JSON 书签文件；Firefox 与浏览历史后续单独评估，以避免首阶段引入数据库依赖和更大的读取范围。每阶段只运行相关行为测试；共享协议或执行层变化时再扩大验证范围。性能改善比例与进程内存数字必须来自实际测量。

### 第一阶段实施记录

Chrome / Edge 书签 Provider 已由 Luna 实现并经主代理审查，自动加入非空 root 搜索。启动时后台预热，后续查询最多每 5 分钟触发一次后台刷新；读取失败保留该配置最后一次成功数据。当前支持标准安装目录中的 Default / Profile 配置，最多 32 个配置和合计 5,000 条书签；文件读取上限 16 MiB，只接受 HTTP(S) URL。URL 路径大小写和 fragment 均保留。

2026-11-05：书签模块 4 项测试通过，覆盖嵌套文件夹、URL 打开、损坏与缺失数据、URL 身份及失败后恢复；格式检查通过。尚未完成真实浏览器桌面验证，首次后台预热完成后需再次查询才能显示新快照，刷新完成不会主动改写当前结果列表。浏览器配置选择界面、Firefox 和浏览历史仍待后续阶段实现。
