# Wowie 开发文档

## 项目结构

```text
src/core/        搜索领域模型、引擎注册表、匹配与排序
src/providers/   内置搜索引擎及应用索引
src/details/     异步详情数据提供者
src/ui/          Slint 窗口、结果模型、交互与详情展示
src/services/    图标、启动等运行时服务
src/platform/    Windows 与其他平台的系统集成
src/plugin.rs    Lua 插件加载、权限和协议转换
ui/              Slint 视图
plugins/         随仓库提供的 Lua 插件
lang/            gettext PO 翻译资源
```

`main.rs` 只负责启动 UI。业务代码不得从 Provider 或插件直接操作 Slint；搜索、网络和图标加载均在后台完成，回到 UI 时必须使用请求代次避免旧结果覆盖新查询。

详情内容和操作按钮的图标先以占位形式显示，再由后台加载并回填。每次替换或清空详情模型都会更新内容代次，过期图标不得写入新模型。共享图标请求在加载异常退出时也必须释放等待者，允许后续请求重试。

空状态图标及详情图片同样在后台读取和解码；查询变化立即使等待中的媒体回填失效。详情图片沿用图标服务的文件大小限制，并限制源图像像素数及显示尺寸。插件动作和执行型 session 的搜索、启动在后台运行；发起时保存查询及 session，完成后仅在当前代次匹配时更新 UI。

配置写入使用同目录临时文件原子替换。配置文件不存在时可使用默认值；现有文件无法读取或解析时，不允许设置编辑或退出时的窗口尺寸保存覆盖它，并在设置窗口显示错误。

后台搜索和分页只计算候选，不发布可执行结果。UI 校验查询代次并接收结果后，才向 `SearchCore::publish_results` 发布同一份共享快照；按 ID 查找时优先使用该快照，避免过期查询或索引刷新改变当前可见行的执行目标。分页按 ID 去重，追加后仍遵守 256 行上限。

## 搜索模型

所有可搜索来源都实现 `SearchEngineProvider`，并通过 `ProviderRegistry` 注册。root search 是注册表对启用引擎的聚合，不是特殊 Provider。具体设置、空查询规则和排序顺序见[搜索引擎架构](搜索引擎架构.md)。

`SearchResult` 表示结果本身，`Action` 表示行为。进入 session 的 `EnterSearchEngine` 只是结果可选的入口动作；搜索引擎可以没有 session，也可以不提供该入口。`Action::ContextMenu` 只在上下文菜单中执行，不会改变结果行的默认行为；其宿主行为包括复制文本、打开网址和启动入口，插件行为由该结果所属插件的 `execute` 回调处理。新增引擎不得通过 `SearchCore`、UI 或插件 ID 分支接入。

插件 root 查询由宿主并行调度并保持稳定合并顺序；单插件结果和 Slint 交互模型都有硬上限。普通 root/session 查询分别有约 150/750ms 的 Lua 指令预算（root 中显式 action word 使用 session 预算），过期请求会在指令钩子处协作取消，但无法中断原生同步 I/O。查询回调中的网络、IPC、文件扫描必须避免阻塞默认搜索，重型数据应在初始化阶段建立索引，或只在明确 session 中分页加载；运行状态中的查询耗时、返回数和截断计数可用于诊断。

空输入的 root search 仅展示明确声明 `ResultVisibility::EmptyQueryOnly` 的入口项。进入 session 后，引擎可在空输入返回介绍或菜单；在没有搜索结果时，还可通过 `SearchEngineProvider::empty_state()` 提供居中的图标、标题、描述和可选详情。`DetailView` 是结果列表右侧的通用详情面板，长内容可通过 `scrollable` 在面板内滚动。

## 内置引擎与快捷指令

- 应用和控制面板索引是独立引擎，共享应用发现快照。
- Calculator、ShortcutProvider 和 Lua 插件都使用相同的引擎接口；Everything 现在作为 Lua 插件提供。
- 内置 `>`（执行命令）、`w`（打开网址）以及用户配置的 URL、应用、命令快捷项，在 root 空输入时是 session 入口；进入后输入参数才执行目标动作。
- 快捷指令不是结果分类。它们使用稳定 ID、普通 `SearchResult` 和 `Action`，分类只描述结果语义。

快捷指令配置位于用户配置的 `shortcuts` 数组。每项支持 `url`、`application`、`command` 三种 `type`，并可选 `description` 和 `placeholder`。进入快捷指令引擎后，`placeholder` 自定义搜索框提示；省略或留空时使用快捷项名称。`mode` 为 `execute`、`search` 或 `panel`；未知或缺失时按 `execute` 处理。配置变更会热加载。

## UI 与窗口

root search 空输入时默认显示结果栏，并使用用户保存的 `window_height`；可用 `compact_search` 收起空输入结果栏，收起时隐藏底部操作提示并将窗口收至搜索行所需高度，按 `↓` 或开始输入后再展开。紧凑空态的搜索框上下边距相同；紧凑态与展开态使用相同的屏幕纵坐标，搜索行不会上下跳动。高度在退出时保存，配置热加载也会立即应用。结果列表统一支持键盘导航、详情面板和上下文操作；菜单支持收藏任意结果，并包括复制名称、路径或网址，以及适用时的打开所在目录、管理员启动和备用启动入口。收藏持久化在 `history.json`，空 root search 将其作为推荐显示，搜索时将匹配的收藏置顶。结果与插件可通过 `context_actions` 增加自己的菜单项，且不改变结果的默认打开动作。空输入的 `↑` 始终用于结果选择，查询历史的记录与恢复数据仍保留，但当前没有按键入口。

启动器的全局快捷键在设置页点击字段后通过按键捕获设置。设置按 `Config` 的顶层结构分为常规、外观、搜索、数据源、快捷项和插件页；宿主字段定义集中在 `src/ui/settings.rs`，UI 行组件位于 `ui/settings.slint`。新增或修改可在设置窗口编辑的 `Config` 字段时，同步维护设置定义、读取显示值与 `apply()` 的写回分支，并为 Rust 可见文本更新 `Settings` 翻译条目。索引文件夹以可添加、编辑、移除的列表管理；Windows 上的“浏览”按钮打开系统文件夹选择窗口，选定后直接保存，粘贴路径仍可使用。保存前检查目录是否存在。自定义快捷项以可展开表单逐项编辑，并在整项提交时检查名称、前缀、类型及目标，配置文件格式仍为 `shortcuts` 数组。内置网页搜索与命令入口的触发词在快捷项设置中配置；插件命令需在 manifest 声明 `customizable_action_words` 后，才能在插件设置中覆盖作者提供的默认触发词。插件统一列在可折叠的“插件”分类下，子项使用滚动列表；每个插件独立管理启用状态、搜索权重和偏好设置。插件偏好由各自 `manifest.json` 的 `preferences` 数组声明，支持文本、密码、布尔、数字和带 `options` 数组的枚举项，宿主将值保存在 `plugins.<id>.preferences`；未声明的插件私有配置仍可由插件从配置对象中读取。枚举设置将配置值与本地化显示文本分开，通过下拉框选择后仍写回原值。分类切换、开关和插件子项展开使用短时属性动画；鼠标悬浮即时反馈。

外观设置中的 `font_family` 留空时使用系统默认字体，`font_size` 为界面基准字号，默认 14、范围 11–20。Slint 视图中的字号使用相对于基准字号的 `rem` 比例，以便一个设置统一缩放各窗口文字。

收藏结果会在结果列表中以星标标识。执行型 session 正在输入时，当前输入生成的即时执行项不提供“添加收藏”，避免它被固定为 session 入口而不是具体命令或网址；空输入下的历史项仍可收藏。session 内的结果不显示用于进入该 session 的 shortcut 提示。

搜索引擎 session 的执行历史与输入框查询历史分开管理。只有成功执行的非空 session 查询会按引擎写入 `history.json`；引擎可用 `SearchEngineSettings.history_limit` 开启并限制数量。内置命令和网址引擎在空输入时将其显示为可再次执行的历史结果，插件则可通过 query 请求中的 `search_history` 自定义呈现。

应用索引会持久化到用户缓存目录。启动时先以目录/文件元数据指纹检查开始菜单、桌面和自定义目录；未变化的来源直接复用缓存，变化时只重扫对应来源。包应用来源以已安装包身份指纹对账，运行期间监听 `PackageCatalog` 包状态事件，并在变化后分别刷新包应用与 AppsFolder 来源；AppsFolder 和控制面板仍每 24 小时完整对账一次，以覆盖应用关闭期间的 Shell 注册变化。插件可用 `wowie.storage_read` / `wowie.storage_write` 在隔离的数据目录中保存自己的索引，缓存版本与过期策略由插件负责。

## 开发准则

- 优先扩展通用的 Engine、Result、Action、DetailView 或插件协议；不要为某个 Provider 或插件在宿主中增加专用分支。
- Provider 返回声明式 `SearchResult`，不访问窗口或 UI model。
- 结果必须使用稳定 `id` 与 `identity`；`ranking_bias` 只用于同层级的微调。
- `separate_launch_entries` 只影响 root 搜索的非空查询；备用启动项以独立稳定结果 ID 显示，默认启动项仍保留原结果，并复用上下文菜单的 `show_advanced_launch_entries` 筛选规则。
- `result_order` 与 `plugin_order` 是用户可调整的有序 ID 列表，只在文本匹配程度相同时影响先后；旧 `result_priorities` 与插件数字权重在配置规范化时迁移为列表顺序。
- 可见性使用 `ResultVisibility` / 插件的 `visible_when`，不要以标题或空字符串作为隐式协议。
- 用户可见 Rust 文本使用 `i18n::tr(language, message_id)`，并同步更新 `lang/en` 与 `lang/zh-CN` 的 PO 条目。
- 修改搜索或协议后至少运行 `cargo test --quiet`；修改 Rust 格式时运行 `cargo fmt --check`。
