# Wowie 开发文档

## 项目结构

```text
src/core/        搜索领域模型、引擎注册表、匹配与排序
src/providers/   内置搜索引擎及应用索引
src/details/     异步详情数据提供者
src/ui/          Slint 窗口、结果模型、交互与详情展示
src/services/    图标、启动等运行时服务
src/platform/    Windows 与其他平台的系统集成
src/plugin.rs    Lua 插件加载、权限和协议转换
ui/              Slint 视图
plugins/         随仓库提供的 Lua 插件
lang/            gettext PO 翻译资源
```

`main.rs` 只负责启动 UI。业务代码不得从 Provider 或插件直接操作 Slint；搜索、网络和图标加载均在后台完成，回到 UI 时必须使用请求代次避免旧结果覆盖新查询。

## 搜索模型

所有可搜索来源都实现 `SearchEngineProvider`，并通过 `ProviderRegistry` 注册。root search 是注册表对启用引擎的聚合，不是特殊 Provider。具体设置、空查询规则和排序顺序见[搜索引擎架构](搜索引擎架构.md)。

`SearchResult` 表示结果本身，`Action` 表示行为。进入 session 的 `EnterSearchEngine` 只是结果可选的入口动作；搜索引擎可以没有 session，也可以不提供该入口。新增引擎不得通过 `SearchCore`、UI 或插件 ID 分支接入。

空输入的 root search 仅展示明确声明 `ResultVisibility::EmptyQueryOnly` 的入口项。进入 session 后，引擎可在空输入返回介绍、菜单或普通空状态。`DetailView` 是通用详情面板；设置 `fullscreen` 后，列表和网格都以全屏方式展示。

## 内置引擎与快捷指令

- 应用和控制面板索引是独立引擎，共享应用发现快照。
- Calculator、Everything、ShortcutProvider 和 Lua 插件都使用相同的引擎接口。
- 内置 `>`（执行命令）、`w`（打开网址）以及用户配置的 URL、应用、命令快捷项，在 root 空输入时是 session 入口；进入后输入参数才执行目标动作。
- 快捷指令不是结果分类。它们使用稳定 ID、普通 `SearchResult` 和 `Action`，分类只描述结果语义。

快捷指令配置位于用户配置的 `shortcuts` 数组。每项支持 `url`、`application`、`command` 三种 `type`，并可选 `description`。`mode` 为 `execute`、`search` 或 `panel`；未知或缺失时按 `execute` 处理。配置变更会热加载。

## UI 与窗口

窗口在真正无结果时使用紧凑高度；出现结果 surface 后恢复用户保存的 `window_height`。高度在退出时保存，配置热加载也会立即应用。结果列表和网格统一支持键盘导航、详情面板和上下文操作；空输入的 `↑` 始终用于结果选择，查询历史的记录与恢复数据仍保留，但当前没有按键入口。

## 开发准则

- 优先扩展通用的 Engine、Result、Action、DetailView 或插件协议；不要为某个 Provider 或插件在宿主中增加专用分支。
- Provider 返回声明式 `SearchResult`，不访问窗口或 UI model。
- 结果必须使用稳定 `id` 与 `identity`；`ranking_bias` 只用于同层级的微调。
- 可见性使用 `ResultVisibility` / 插件的 `visible_when`，不要以标题或空字符串作为隐式协议。
- 用户可见 Rust 文本使用 `i18n::tr(language, message_id)`，并同步更新 `lang/en` 与 `lang/zh-CN` 的 PO 条目。
- 修改搜索或协议后至少运行 `cargo test --quiet`；修改 Rust 格式时运行 `cargo fmt --check`。
