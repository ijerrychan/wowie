# 插件开发

Wowie 插件使用内嵌 Lua VM 运行。用户无需安装 Lua、Python 或 Node，插件也不会作为独立进程启动。

## 目录结构

```text
plugins/github/
├── manifest.json
├── main.lua
└── icons/
```

## Manifest

```json
{
  "id": "github",
  "name": "GitHub",
  "version": "1.0.0",
  "api_version": 1,
  "entry_point": "main.lua",
  "keywords": ["github", "gh"],
  "engine": {
    "participates_in_root": true,
    "respect_global_fuzzy_search": true,
    "ranking_bias": 0
  },
  "commands": [
    {
      "id": "search",
      "title": "Search GitHub",
      "action_words": ["gh"],
      "mode": "search",
      "require_separator": true,
      "presentation": "list",
      "icon": {"type": "named", "id": "github"}
    }
  ]
}
```

插件快捷命令只作用于搜索场景：`keywords` 参与默认搜索，`action_words` 切换到插件搜索引擎，结果的 `aliases` 提供结果级别的搜索别名。快捷命令不是结果类型，插件结果应按其自身语义分类。插件不能注册全局快捷键。`mode` 描述 action word 进入的搜索引擎交互：`search`（默认）持续显示 Provider 结果，`execute` 将 Enter 解释为直接动作，`panel` 在 Enter 时打开结果的详情面板。`require_separator` 为 `true` 时，必须在 action word 后输入空白字符才会触发 command；省略时保持兼容旧插件的无分隔符触发行为。`presentation` 当前支持 `list`（默认）和 `grid`，用于声明该 command 的结果视图提示；视图仍由宿主统一控制。

插件通过 `wowie.result` 返回的普通结果可设置 `visible_when = "empty_query"`。该结果只在当前 session（或 root search）的输入为空时保留，开始输入后宿主会在匹配和排序前将它移除；省略或设置 `"always"` 时保持常规行为。这可用于空 session 的介绍、选项菜单、提示项和快捷入口。结果仍可设置图标、`detail`、`actions`、`session_updates` 与 `session_entry`，不再存在专用 intro 协议。

`detail.fullscreen = true` 可要求详情在 list 或 grid 视图中均使用全屏面板；适合功能介绍、向导和表单。默认值为 `false`，在 list 视图保持右侧详情栏。

`engine` 控制插件作为搜索引擎的默认行为，而不是结果类型：`participates_in_root` 决定是否加入 root search，`respect_global_fuzzy_search` 决定是否遵从用户的模糊搜索开关，`ranking_bias` 是 -100 至 100 的末级同分偏置。省略时等价于上述默认值。插件结果的 `ranking_bias` 也会被限制在该范围；不得用它压过更强的文本匹配或使用历史。需要独立搜索上下文时再声明 `commands`；只有希望用户从 root 的普通结果进入该 session 时，才设置 `session_entry = true`。

搜索引擎页面不是插件自绘 UI。插件通过 `query` 返回统一结果，通过结果的 `detail` 和 `detail.actions` 定义可交互面板；宿主统一处理页面标题、返回、焦点、网格导航和异步代次校验。需要新的搜索引擎时，在 manifest 中声明 command；宿主侧 Rust 实现则使用独立的 `SearchEngineProvider`，而不是普通 `DynamicProvider`。

Manifest 可以声明受控权限，例如 `network`、`clipboard`、`download` 和 `filesystem`。权限只开放对应的宿主 API，不允许插件自行创建进程或访问宿主 UI。

## Lua API

插件通过 `wowie.on` 注册回调：

### Session 菜单结果

搜索引擎插件可在结果项中返回 `session_updates`（字符串键值表）。该结果项会成为会话内菜单项：用户点击后，宿主只更新当前 `SearchEngineSession` 的临时状态并重新调用 `query`，不会执行外部动作，也不会把状态保存到插件偏好。Lua 的 `context.session` 可读取当前状态；空字符串会移除对应键。例如：

```lua
wowie.result({
    id = "choose-source",
    title = "源语言",
    session_updates = { menu = "source" }
})
```

后续 `query` 可在 `context.session.menu == "source"` 时返回语言列表；语言项用 `{ source = "EN", menu = "" }` 即可回到主菜单。这让会话自然退化为层级菜单，同时仍复用统一结果列表、焦点和返回行为。

默认搜索页中的插件入口可在结果项设置 `command_id` 与 `session_entry = true`。宿主会将其转换为进入该 command 的搜索会话，适合“用某服务搜索”一类自定义结果；命令的图标会自动复用到入口和会话搜索框。

插件返回的结果由插件自己的 `query` 回调决定候选集合；宿主随后仍会对所有结果统一执行标题/别名匹配、排序和 fallback 处理。插件应在回调中使用 `wowie.fuzzy_match` 做候选筛选，避免与宿主算法产生差异。

```lua
wowie.on("query", function(query, context)
    return {
        request_id = context.request_id,
        items = {
            wowie.result({
                id = "hello",
                title = "Hello " .. query,
                subtitle = context.preferences.endpoint,
                aliases = {"hi"},
                icon = {type = "named", id = "calculator"},
                actions = {
                    wowie.action("open", {type = "named", id = "calculator"})
                },
                detail = {
                    title = "Details",
                    blocks = {
                        {type = "text", text = "Rendered by Wowie"},
                        {type = "metric", label = "Status", value = "Ready"},
                        {type = "icon", glyph = "★", icon = {type = "named", id = "calculator"}}
                    },
                    actions = {
                        {id = "open", title = "Open"}
                    },
                    width = {preferred = 480, min = 320, max = 640},
                    height = {min = 280}
                }
            })
        }
    }
end)

wowie.on("execute", function(item_id, action_id, context)
    return {
        request_id = context.request_id,
        title = "Executed " .. action_id,
        subtitle = item_id
    }
end)
```

需要异步加载详情（例如天气、网络预览）时，可注册 `detail` 回调。宿主会在后台工作线程调用
`wowie.on("detail", function(item_id, context) ...)`，回调返回
`{request_id = context.request_id, detail = {...}}`；详情结构与结果项的 `detail` 相同。
插件可以在 Lua 侧自行缓存网络结果，宿主不会为插件加入专用 provider 分支。
如果希望回车只打开详情面板而不执行启动动作，可返回 `wowie.action("open_detail")`；它是统一结果 Action，
后续也可以扩展为其他显式快捷键触发方式。

### 结果行为接口

结果项的 `actions` 是统一行为接口，而不是插件或 provider 的私有协议。行为按归属分为三类：

- 系统行为：例如 `Launch`，由平台打开文件、程序或 URL。
- Wowie 行为：例如进入搜索 session、更新 session 状态、`open_detail` 打开详情面板。
- 插件行为：由 `wowie.action(id)` 创建，宿主通过插件的 `execute` 回调分派。

宿主会根据行为类型统一处理回车、上下文菜单、详情面板和插件执行；provider 只负责声明结果及其行为，
不应在 provider 中直接操作窗口或自行实现另一套启动逻辑。

当前内置函数：

- `wowie.on(method, callback)`：注册 `query`、`execute`，以及后续宿主生命周期回调。
- `wowie.result(table)`：标记一个搜索结果。
- `wowie.results(array)`：包装结果数组。
- `wowie.action(id, icon?)`：创建结果 Action。
- `wowie.locale()`：读取当前 locale；`wowie.locale("current")` 读取当前 locale，其他 key 暂时返回 fallback locale。
- `wowie.url_encode(value)`：使用宿主 URL 编码规则编码查询参数；路径片段请使用 `wowie.url_encode_path`。
- `wowie.url_encode_path(value)`：使用 RFC 3986 百分号编码单个 URL 路径片段；与查询参数编码区分。
- `wowie.http_get_json(url)` / `wowie.http_get_text(url)`：通过宿主共享 HTTP 客户端读取受限大小的 HTTP(S) 响应，需要 `network` 权限。
- `wowie.http_post_form_json(url, form)`：提交 URL 编码表单并读取 JSON 响应，需要 `network` 权限；适合 DeepL 等只开放 POST 的 API。
- `wowie.http_post_json(url, body, headers?)`：提交 JSON 请求体并读取 JSON 响应，需要 `network` 权限；可选请求头适合 Google `application/json+protobuf` 等 API。
- `wowie.clipboard_set(text)`：写入系统剪贴板，需要 `clipboard` 权限。
- `wowie.download(url, filename)`：下载到用户 Downloads 目录，使用安全文件名且避免覆盖已有文件，需要 `network` 和 `download` 权限。
- `wowie.env(name)`：读取指定环境变量，需要 `filesystem` 权限；不存在时返回 `nil`。
- `wowie.fs_read_text(path)`：读取不超过 4 MiB 的文本文件；路径不存在时返回 `nil`，需要 `filesystem` 权限。
- `wowie.fs_list(path)`：列出目录项（`name`、`path`、`is_dir`、`size`），单次最多 4096 项，需要 `filesystem` 权限。插件可用这些通用 API 自己实现本地 provider 的发现和匹配，无需在 Rust 宿主中增加专用 provider。
- `wowie.fuzzy_match(text, query)`：使用宿主统一的 nucleo 模糊匹配算法返回布尔值。插件 provider 应调用它决定自己的结果是否匹配。
- 详情文本块可设置 `copyable = true`；只有这类 `text`/`markdown` 块使用可选择的只读文本控件，默认文本仍使用轻量渲染。
- 图标还可以使用 `{type = "file", path = absolute_image_path}` 引用文件系统中的 PNG/JPEG 图标；该引用仅适用于声明了 `filesystem` 权限的本地 provider 插件。

## 宿主边界

Lua 插件只返回声明式数据，不直接操作 Slint、窗口句柄或宿主控件。图标使用 `resource`、`system`、`named`、`remote` 四种引用；`resource` 支持插件目录内的 PNG、ICO 和 SVG，`remote` 只允许宿主通过 HTTP(S) 获取并限制响应大小。宿主会限制文件大小和渲染尺寸。插件可以自带 SVG 图标，例如：

```lua
icon = {type = "resource", path = "icons/my-icon.svg"}
```

远程图标示例：

```lua
icon = {type = "remote", url = "https://example.com/icon.svg"}
```

详情面板支持 `text`、`markdown`、`metric`、`icon`、`weather`、`image`、`code`、`table`、`link`、`loading`、`error`、`separator` 和 DetailAction。`image` 只能引用插件目录内的资源；`link` 只允许 `http://` 或 `https://`。代码、表格和 Markdown 都是声明式文本数据，插件不需要依赖 Slint。详情可通过 `scrollable = true` 允许滚动，内容过期或加载失败时由宿主统一显示加载/错误状态。
详情面板中的 `text` 和 `markdown` 文本块使用只读文本输入控件呈现，用户可以拖拽选中文字并使用 `Ctrl+C` 复制到系统剪贴板；插件无需自行声明复制 action 或调用 UI API。

网络请求使用宿主统一的超时和大小限制；插件不应自行调用外部命令或依赖用户环境。查询中的网络操作运行在搜索工作线程，详情 Action 的网络、剪贴板和下载操作由宿主放入独立工作线程。
## 当前架构说明（2026-09）

插件由 `src/plugin.rs` 负责加载、Lua VM 生命周期、权限 API、协议转换和 action 执行。插件在宿主侧以现有 `SearchEngineProvider` 接口注册：它可以向默认搜索贡献结果，也可以在 shortcut 进入后提供 session 结果；插件不需要在 `SearchCore`、`ProviderRegistry`、UI 或具体 provider 中增加专用分支。

默认搜索流程如下：

```text
PluginManager
    -> SearchEngineProvider::query()
    -> ProviderRegistry 汇总结果
    -> SearchCore 统一匹配、排序
    -> Slint ResultRow
```

插件的 `query` 回调负责决定候选集合；返回的结果随后仍会经过宿主统一的 nucleo 匹配器和排序器。需要与宿主保持一致时，应使用 `wowie.fuzzy_match(text, query)` 进行候选判断，而不是复制一套匹配算法。

插件命令、session、结果 action、详情面板和图标都通过统一的 `SearchResult`、`Action`、`SearchEngineSession` 和 `IconSpec` 数据模型传递。插件不直接操作 Slint，也不直接创建线程、进程或窗口。
