# 插件开发

Wowie 插件使用内嵌 Lua VM 运行。用户无需安装 Lua、Python 或 Node，插件也不会作为独立进程启动。

## 目录结构

```text
plugins/github/
├── manifest.json
├── main.lua
└── icons/
```

## Manifest

```json
{
  "id": "github",
  "name": "GitHub",
  "version": "1.0.0",
  "api_version": 1,
  "entry_point": "main.lua",
  "keywords": ["github", "gh"],
  "engine": {
    "participates_in_root": true,
    "respect_global_fuzzy_search": true,
    "ranking_bias": 0
  },
  "commands": [
    {
      "id": "search",
      "title": "Search GitHub",
      "action_words": ["gh"],
      "mode": "search",
      "placeholder": "Search repositories and issues",
      "require_separator": true,
      "icon": {"type": "named", "id": "github"}
    }
  ]
}
```

插件快捷命令只作用于搜索场景：`keywords` 参与默认搜索，`action_words` 切换到插件搜索引擎，结果的 `aliases` 提供结果级别的搜索别名。快捷命令不是结果类型，插件结果应按其自身语义分类。插件不能注册全局快捷键。`mode` 描述 action word 进入的搜索引擎交互：`search`（默认）持续显示 Provider 结果，`execute` 将 Enter 解释为直接动作，`panel` 在 Enter 时打开结果的详情面板。可选的 `placeholder` 自定义进入该 command 后搜索框的提示文字；省略或留空时使用 command 标题。`title` 与 `placeholder` 若与 `lang/*/LC_MESSAGES/wowie.po` 中 `Launcher` context 的 `msgid` 相同，会由宿主按当前语言本地化。`require_separator` 为 `true` 时，必须在 action word 后输入空白字符才会触发 command；省略时保持兼容旧插件的无分隔符触发行为。所有 session 结果统一使用列表视图。

插件作者可为单个 command 设置 `customizable_action_words: true`，允许用户在设置窗口覆盖该 command 的 `action_words`。省略或设为 `false` 时，触发词由插件作者管理，UI 不提供覆盖字段。覆盖值由宿主存入 `plugins.<plugin_id>.command_action_words.<command_id>`；用户留空时恢复 manifest 中声明的默认值。新增触发词应保持简短、唯一，且不要与宿主内置快捷项或其他插件的触发词冲突。

插件通过 `wowie.result` 返回的普通结果可设置 `visible_when = "empty_query"`。该结果只在当前 session（或 root search）的输入为空时保留，开始输入后宿主会在匹配和排序前将它移除；省略或设置 `"always"` 时保持常规行为。这可用于空 session 的介绍、选项菜单、提示项和快捷入口。结果仍可设置图标、`detail`、`actions`、`context_actions`、`session_updates` 与 `session_entry`，不再存在专用 intro 协议。

自定义结果可通过 `SearchResult.allow_favorite`（Rust）或 `allow_favorite`（Lua 插件结果）声明是否允许收藏。Lua 字段省略时普通结果默认允许收藏，带 `session_updates` 的会话选项默认禁止收藏；需要时可显式设置 `true` 或 `false` 覆盖默认值。宿主会隐藏不允许收藏结果的“添加到收藏”菜单项，并在收藏存储层拒绝添加操作。

详情始终显示在结果列表右侧的详情栏中。设置 `detail.scrollable = true` 可让长内容在详情栏内滚动；详情布局固定在列表右侧。

图片详情块由宿主在后台读取和解码，源文件上限为 4 MiB，解码前检查源图像的像素数量，显示图片最长边缩至 256 像素；大图请提供适合预览的副本。

搜索引擎插件可通过 `wowie.on("empty_state", function(context) ... end)` 为无结果页面提供标题、描述和图标；可选的 `detail` 会在用户激活页面时打开。宿主仅在当前查询没有结果时调用它，context 包含 `command_id`、`query`、`session`、locale 和 request id。空页面不需要伪造结果项。要动态提供 session 搜索框图标，可注册 `search_engine_icon` 回调并返回 `{request_id = context.request_id, icon = {type = "system", target = path}}`；未注册时继续使用 manifest 中 command 的静态图标。

`engine` 控制插件作为搜索引擎的默认行为，而不是结果类型：`participates_in_root` 决定是否加入 root search，`respect_global_fuzzy_search` 决定是否遵从用户的模糊搜索开关，`ranking_bias` 是 -100 至 100 的末级同分偏置，`history_limit` 决定保留多少条成功执行过的 session 查询（默认 0，宿主最多保存 50 条）。省略时等价于上述默认值。插件结果的 `ranking_bias` 也会被限制在该范围；不得用它压过更强的文本匹配或使用历史。需要独立搜索上下文时再声明 `commands`；只有希望用户从 root 的普通结果进入该 session 时，才设置 `session_entry = true`。

当插件引擎设置了非零 `history_limit` 且当前 session 查询为空时，`query` 回调会收到 `context.search_history` 数组。每项包含原始 `query` 和稳定的 `result_id`。插件可据此返回普通、可执行的历史结果，也可忽略该字段；宿主只在插件结果成功执行后持久化查询，按引擎隔离并将最近使用的查询排在前面。例如可用 `result_id` 作为历史结果 ID 的组成部分，确保同一目标从不同历史查询产生时仍能独立呈现。

`engine.search_debounce_ms` 设置输入停止后多久执行 session 查询，单位为毫秒，默认 30，宿主最多采用 2000。依赖远端 API 的插件可提高该值，以减少用户输入时产生的重复请求。

搜索引擎页面不是插件自绘 UI。插件通过 `query` 返回统一结果，通过结果的 `detail` 和 `detail.actions` 定义可交互面板；宿主统一处理页面标题、返回、焦点和异步代次校验。需要新的搜索引擎时，在 manifest 中声明 command；宿主侧 Rust 实现则使用独立的 `SearchEngineProvider`，而不是普通 `DynamicProvider`。

Manifest 可以声明受控权限，例如 `network`、`clipboard`、`download`、`filesystem` 和 `everything`。权限只开放对应的宿主 API，不允许插件自行创建进程或访问宿主 UI。

## Lua API

插件可用 `wowie.storage_read(key)` / `wowie.storage_write(key, value)` 持久化自己的 JSON 索引数据。数据写入用户数据目录下按插件 ID 隔离的专属目录；key 只允许字母、数字、点、下划线和连字符，单项上限 8 MiB。该 API 不需要 `filesystem` 权限，也不能访问其他插件或宿主缓存。插件应自行保存 schema 版本和更新时间，并在索引来源变化或缓存过期时重建；推荐先用缓存响应查询，再按需刷新。

插件通过 `wowie.on` 注册回调：

### Session 菜单结果

搜索引擎插件可在结果项中返回 `session_updates`（字符串键值表）。该结果项会成为会话内菜单项：用户点击后，宿主只更新当前 `SearchEngineSession` 的临时状态并重新调用 `query`，不会执行外部动作，也不会把状态保存到插件偏好。Lua 的 `context.session` 可读取当前状态；空字符串会移除对应键。例如：

```lua
wowie.result({
    id = "choose-source",
    title = "源语言",
    allow_favorite = false,
    session_updates = { menu = "source" }
})
```

后续 `query` 可在 `context.session.menu == "source"` 时返回语言列表；语言项用 `{ source = "EN", menu = "" }` 即可回到主菜单。这让会话自然退化为层级菜单，同时仍复用统一结果列表、焦点和返回行为。

### 结果上下文菜单

`context_actions` 用于声明仅出现在该结果右键/快捷键菜单中的插件操作，与点击结果或按 Enter 时执行的 `actions` 相互独立。每项包含稳定的 `id`、显示用 `title`、可选 `subtitle` 和 `icon`；选中菜单项时宿主以该结果的 `item_id` 与菜单项 `id` 调用插件的 `execute` 回调：

```lua
wowie.result({
    id = "repository",
    title = "Wowie",
    context_actions = {
        {
            id = "copy-clone-url",
            title = "Copy clone URL",
            subtitle = "Copy the HTTPS clone address",
            icon = {type = "named", id = "content-copy"}
        }
    }
})

wowie.on("execute", function(item_id, action_id, context)
    if item_id == "repository" and action_id == "copy-clone-url" then
        wowie.clipboard_set("https://example.com/wowie.git")
        return {request_id = context.request_id, title = "Clone URL copied"}
    end
    return {request_id = context.request_id, title = "Unsupported action"}
end)
```

插件若调用剪贴板等受限 API，仍须在 manifest 声明对应权限。宿主统一提供复制结果名称、复制本地路径/网址、打开所在目录、管理员启动和备用启动入口等通用操作；插件只需声明自身特有的菜单项，不负责绘制或定位菜单。

默认搜索页中的插件入口可在结果项设置 `command_id` 与 `session_entry = true`。宿主会将其转换为进入该 command 的搜索会话，适合“用某服务搜索”一类自定义结果；命令的图标会自动复用到入口和会话搜索框。

插件返回的结果由插件自己的 `query` 回调决定候选集合；宿主随后仍会对所有结果统一执行标题/别名匹配、排序和 fallback 处理。插件应在回调中使用 `wowie.fuzzy_match` 做候选筛选，避免与宿主算法产生差异。

默认 root search 会并行调用启用且声明参与 root 的插件；结果仍按 manifest 顺序合并，
因此并行不会改变稳定排序。宿主会限制每个插件单次 root 查询最多贡献 128 项、session
查询最多贡献 256 项，交互界面最多渲染 256 行。插件应优先返回最相关的结果，不能依赖
宿主接收无限结果；当前 Lua session 也使用该硬上限，后续需要更多内容时再扩展分页协议，
而不是在一次 `query` 中返回数千项。

session 查询上下文包含 `offset` 和 `limit`。插件可以根据它们返回后续页面；宿主会在
结果接近当前页面末尾时调用下一页，并按结果 ID 去重。未实现分页的插件可以忽略这两个
字段，但仍应只返回最相关的前 `limit` 项。

分页追加后交互模型仍最多保留 256 行；达到上限后不再请求后续页面。被新查询替代的旧页面不会修改当前显示结果的执行数据。

宿主在将回调结果转换为 Rust 模型前会执行协议边界校验：插件入口脚本最多 2 MiB，manifest
最多 256 KiB；`query` 和 `detail` 响应最多 8 MiB，`initialize`、`execute`、`empty_state`
和 `search_engine_icon` 响应最多 512 KiB。JSON 最多嵌套 32 层、包含 20,000 个值，字符串
总量最多 2 MiB；单次 query 最多 512 个原始结果。宿主还会限制结果 ID、标题、别名、动作、
详情块、表格行列和详情文本长度，超限数据会被拒绝或截断并记录错误。`storage_read` 与
`storage_write` 继续使用 8 MiB 单项上限，并使用同一 JSON 结构预算。

`query` 回调运行在搜索工作线程中，但 Lua VM、网络、IPC 和文件 API 仍是同步操作；
不要在默认查询中执行全盘扫描或网络请求。初始化阶段建立内存索引，查询阶段只做轻量
匹配；网络或昂贵操作应放入明确的 session，并通过详情或分页逐步加载。无 action word 的旧 root 查询
在插件 VM 忙碌时会被跳过，宿主还会用查询代次让并行任务在返回前放弃过期结果，因此
插件不应假设每次 `query` 都一定完成。宿主会为 root 查询提供约 150ms、session 查询提供约
750ms 的 Lua 指令预算（root 中显式 action word 使用 session 预算）；过期查询也会在 Lua 指令钩子触发时协作取消。该机制不能中断正在执行
的原生同步网络、IPC 或文件 I/O，因此这些操作仍应由插件避免或移入明确的 session。插件状态
中的 `last_query_ms`、`last_query_results` 和 `query_truncations` 可用于定位慢查询及结果截断。

```lua
wowie.on("query", function(query, context)
    return {
        request_id = context.request_id,
        items = {
            wowie.result({
                id = "hello",
                title = "Hello " .. query,
                subtitle = context.preferences.endpoint,
                aliases = {"hi"},
                icon = {type = "named", id = "calculator"},
                actions = {
                    wowie.action("open", {type = "named", id = "calculator"})
                },
                detail = {
                    title = "Details",
                    blocks = {
                        {type = "text", text = "Rendered by Wowie"},
                        {type = "metric", label = "Status", value = "Ready"},
                        {type = "icon", glyph = "★", icon = {type = "named", id = "calculator"}}
                    },
                    actions = {
                        {id = "open", title = "Open"}
                    },
                    width = {preferred = 480, min = 320, max = 640},
                    height = {min = 280}
                }
            })
        }
    }
end)

wowie.on("execute", function(item_id, action_id, context)
    return {
        request_id = context.request_id,
        title = "Executed " .. action_id,
        subtitle = item_id
    }
end)
```

需要异步加载详情（例如天气、网络预览）时，可注册 `detail` 回调。宿主会在后台工作线程调用
`wowie.on("detail", function(item_id, context) ...)`，回调返回
`{request_id = context.request_id, detail = {...}}`；详情结构与结果项的 `detail` 相同。
插件可以在 Lua 侧自行缓存网络结果，宿主不会为插件加入专用 provider 分支。
如果希望回车只打开详情面板而不执行启动动作，可返回 `wowie.action("open_detail")`；它是统一结果 Action，
后续也可以扩展为其他显式快捷键触发方式。

### 结果行为接口

结果项的 `actions` 是点击结果时使用的统一行为接口，而不是插件或 provider 的私有协议。行为按归属分为三类：

- 系统行为：例如 `Launch`，由平台打开文件、程序或 URL。
- Wowie 行为：例如进入搜索 session、更新 session 状态、`open_detail` 打开详情面板。
- 插件行为：由 `wowie.action(id)` 创建，宿主通过插件的 `execute` 回调分派。

`context_actions` 则专门声明结果级菜单操作，不会改变结果的默认打开行为。宿主根据声明统一处理上下文菜单、详情面板和插件执行；provider 只负责声明结果及其行为，
不应在 provider 中直接操作窗口或自行实现另一套启动逻辑。

当前内置函数：

- `wowie.on(method, callback)`：注册 `query`、`execute`，以及后续宿主生命周期回调。
- `wowie.result(table)`：标记一个搜索结果。
- `wowie.results(array)`：包装结果数组。
- `wowie.action(id, icon?)`：创建结果 Action。
- `wowie.locale()`：读取当前 locale；`wowie.locale("current")` 读取当前 locale，其他 key 暂时返回 fallback locale。
- `wowie.url_encode(value)`：使用宿主 URL 编码规则编码查询参数；路径片段请使用 `wowie.url_encode_path`。
- `wowie.url_encode_path(value)`：使用 RFC 3986 百分号编码单个 URL 路径片段；与查询参数编码区分。
- `wowie.http_get_json(url)` / `wowie.http_get_text(url)`：通过宿主共享 HTTP 客户端读取受限大小的 HTTP(S) 响应，需要 `network` 权限。
- `wowie.http_post_form_json(url, form)`：提交 URL 编码表单并读取 JSON 响应，需要 `network` 权限；适合 DeepL 等只开放 POST 的 API。
- `wowie.http_post_json(url, body, headers?)`：提交 JSON 请求体并读取 JSON 响应，需要 `network` 权限；可选请求头适合 Google `application/json+protobuf` 等 API。
  JSON 响应上限为 8 MiB；所有 HTTP 响应均在读取过程中执行大小限制，即使服务器未提供 `Content-Length` 也不会完整读入超限响应。
- `wowie.clipboard_set(text)`：写入系统剪贴板，需要 `clipboard` 权限。
- `wowie.download(url, filename)`：下载到用户 Downloads 目录，使用安全文件名且避免覆盖已有文件，需要 `network` 和 `download` 权限。
- `wowie.env(name)`：读取指定环境变量，需要 `filesystem` 权限；不存在时返回 `nil`。
- `wowie.fs_read_text(path)`：读取不超过 4 MiB 的文本文件；路径不存在时返回 `nil`，需要 `filesystem` 权限。
- `wowie.fs_list(path)`：列出目录项（`name`、`path`、`is_dir`、`size`），单次最多 4096 项，需要 `filesystem` 权限。插件可用这些通用 API 自己实现本地 provider 的发现和匹配，无需在 Rust 宿主中增加专用 provider。
- `wowie.everything_search(query, offset?, limit?)`：通过 Everything IPC 查询文件，返回包含 `name` 和绝对 `path` 的数组，需要 `everything` 权限；仅 Windows 上可用，结果数量受宿主上限限制。
- `wowie.everything_icon_target()`：返回 Everything 可执行文件路径，供插件结果声明系统图标；未找到或非 Windows 时返回 `nil`，需要 `everything` 权限。
- `wowie.fuzzy_match(text, query)`：使用宿主统一的 nucleo 模糊匹配算法返回布尔值。插件 provider 应调用它决定自己的结果是否匹配。
- 详情文本块可设置 `copyable = true`；只有这类 `text`/`markdown` 块使用可选择的只读文本控件，默认文本仍使用轻量渲染。
- 图标还可以使用 `{type = "file", path = absolute_image_path}` 引用文件系统中的 PNG/JPEG 图标；该引用仅适用于声明了 `filesystem` 权限的本地 provider 插件。

## 宿主边界

Lua 插件只返回声明式数据，不直接操作 Slint、窗口句柄或宿主控件。图标使用 `resource`、`system`、`named`、`remote` 四种引用；`resource` 支持插件目录内的 PNG、ICO 和 SVG，`remote` 只允许宿主通过 HTTP(S) 获取并限制响应大小。宿主会限制文件大小和渲染尺寸。插件可以自带 SVG 图标，例如：

```lua
icon = {type = "resource", path = "icons/my-icon.svg"}
```

远程图标示例：

```lua
icon = {type = "remote", url = "https://example.com/icon.svg"}
```

详情面板支持 `text`、`markdown`、`metric`、`icon`、`weather`、`image`、`code`、`table`、`link`、`loading`、`error`、`separator` 和 DetailAction。`image` 只能引用插件目录内的资源；`link` 只允许 `http://` 或 `https://`。代码、表格和 Markdown 都是声明式文本数据，插件不需要依赖 Slint。详情可通过 `scrollable = true` 允许滚动，内容过期或加载失败时由宿主统一显示加载/错误状态。
详情面板中的 `text` 和 `markdown` 文本块使用只读文本输入控件呈现，用户可以拖拽选中文字并使用 `Ctrl+C` 复制到系统剪贴板；插件无需自行声明复制 action 或调用 UI API。

网络请求使用宿主统一的超时和大小限制；插件不应自行调用外部命令或依赖用户环境。查询中的网络操作运行在搜索工作线程，详情 Action 的网络、剪贴板和下载操作由宿主放入独立工作线程。

## 插件设置

插件可在 `manifest.json` 声明需要展示在宿主设置窗口中的偏好项。每项使用稳定的 `key`、显示用 `title`、可选 `description`、`type` 和 `default`。当前支持 `text`、`password`、`boolean`、`number` 和 `enum`；枚举项通过 `options` 数组声明可选值，并在设置界面以下拉菜单显示。`password` 在设置界面中以密码输入框显示。宿主将修改值保存到 `plugins.<插件 id>.preferences`，并在后续插件请求的 `context.preferences` 中提供。

```json
{
  "preferences": [{
    "key": "api_key",
    "title": "Service API key",
    "description": "Optional key used by this plugin.",
    "type": "password",
    "default": ""
  }]
}
```

枚举设置示例：

```json
{
  "preferences": [{
    "key": "region",
    "title": "Region",
    "type": "enum",
    "options": ["us", "eu", "asia"],
    "default": "us"
  }]
}
```

插件搜索优先级也可以在插件自己的设置页调整。`plugins.<id>.weight` 默认是 `0`，范围为 -1000 至 1000；它只做小幅排序微调。无需用户界面时，插件仍可在 `preferences` 中读取自行维护的配置项，但只有清单声明的偏好会自动生成控件。
## 当前架构说明（2026-09）

插件由 `src/plugin.rs` 负责加载、Lua VM 生命周期、权限 API、协议转换和 action 执行。插件在宿主侧以现有 `SearchEngineProvider` 接口注册：它可以向默认搜索贡献结果，也可以在 shortcut 进入后提供 session 结果；插件不需要在 `SearchCore`、`ProviderRegistry`、UI 或具体 provider 中增加专用分支。

默认搜索流程如下：

```text
PluginManager
    -> SearchEngineProvider::query()
    -> ProviderRegistry 汇总结果
    -> SearchCore 统一匹配、排序
    -> Slint ResultRow
```

插件的 `query` 回调负责决定候选集合；返回的结果随后仍会经过宿主统一的 nucleo 匹配器和排序器。需要与宿主保持一致时，应使用 `wowie.fuzzy_match(text, query)` 进行候选判断，而不是复制一套匹配算法。

插件命令、session、结果 action、详情面板和图标都通过统一的 `SearchResult`、`Action`、`SearchEngineSession` 和 `IconSpec` 数据模型传递。插件不直接操作 Slint，也不直接创建线程、进程或窗口。
