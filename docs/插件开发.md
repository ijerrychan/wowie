# 插件开发：JSON Lines 与内嵌 Lua

当前插件实现暂时跳过文件搜索，优先验证“Launcher → Provider → Item → Action”的闭环。插件本地化由插件自己维护，暂不提供跨插件共享翻译目录。Launcher 内置 Rust 文案使用统一 PO i18n；插件不能直接调用 Launcher 的 `i18n::tr()`，应继续通过自己的 `locales/*.json` 和 message key 提供本地化文本。

## 目录与 Manifest

把插件放在项目目录的 `plugins/<id>/` 下，或用户数据目录的 `Wowie/plugins/<id>/` 下：

```json
{
  "id": "github",
  "name": "GitHub",
  "version": "0.1.0",
  "api_version": 1,
  "runtime": "lua",
  "entry_point": "main.lua",
  "keywords": ["gh", "github"],
  "permissions": ["network"]
}
```

`runtime` 是可执行文件名，`entry_point` 是相对于插件目录的脚本入口。因此 Lua、Python、Node 或自定义可执行程序都可以使用同一个协议。该模式要求用户提供对应运行时；它主要用于兼容性和快速验证，不是 wowie 的最终 Lua 插件架构。

## 目标架构：内嵌 Lua

wowie 计划参考 mpv：在 Launcher 内部嵌入 Lua 虚拟机，直接加载插件目录中的 `main.lua`。Lua 由 wowie 自带，用户不需要安装 Lua；插件进程也不会因为查询而反复启动。

```text
wowie.exe
  ├─ Rust 宿主能力
  ├─ Lua VM（内置）
  ├─ wowie Lua API
  └─ plugins/everything/main.lua
```

Lua 插件通过宿主 API 获取能力，而不是自行调用 PowerShell、Python 或外部命令：

```lua
function on_query(query)
    return wowie.result {
        id = "example:item",
        title = "Example",
        subtitle = query,
        actions = { wowie.action("open") }
    }
end

wowie.on("query", on_query)
```

宿主 API 的设计原则：

- Everything IPC、文件访问、进程启动等平台能力由 Rust 宿主实现。
- Lua 只表达 Provider、Result 和 Action，不直接操作 Slint UI 或 Windows HWND。
- 每个插件使用独立 Lua 状态，并捕获脚本异常，避免插件错误退出 Launcher。
- 查询和 Action 回调需要有取消、超时和退出清理机制。
- API 以稳定的消息和数据结构为边界，不暴露内部 Rust 类型。

Everything 插件计划使用：

```lua
local items = wowie.everything.search(query)
return wowie.results(items)
```

其中 `wowie.everything.search` 由 Rust 调用 Everything 的本地 IPC；Lua 插件不依赖 Everything 命令行工具，也不依赖 Python。

## JSON Lines 协议

默认兼容模式下，Launcher 每次查询启动一个短生命周期进程，向 stdin 写入一行：

```json
{"method":"query","query":"github react","api_version":1,"locale":"zh-CN"}
```

插件向 stdout 返回一行：

```json
{
  "items": [
    {
      "id": "facebook/react",
      "title": "facebook/react",
      "subtitle": "A JavaScript library for building user interfaces",
      "aliases": ["react"],
      "icon": {"type": "resource", "path": "icons/github.png"},
      "actions": [{"id": "open"}, {"id": "copy-url"}]
    }
  ]
}
```

Item 是 Launcher 的统一对象，不是插件私有 UI。`title`、`subtitle`、`actions` 和可选的 `detail` 共同描述结果；插件不直接绘制 Slint UI。

## 图标

Item 可以携带插件图标：

```json
"icon": {"type": "resource", "path": "icons/github.png"}
```

`resource` 路径相对于插件目录，当前支持 PNG；插件管理器会把它解析为插件资源文件。也可以复用系统图标：

```json
"icon": {"type": "system", "target": "C:\\Windows\\System32\\cmd.exe"}
```

`system` 的 target 会交给平台图标提供器处理，因此可以使用 `.exe`、文件路径或系统 Shell 目标。插件图标优先于默认的 launch target 图标，无法读取时会自动回退到系统默认图标。

## 当前边界

- 已支持：脚本插件发现、Manifest、动态 Search、统一 SearchResult、插件 Action 执行。
- 暂未支持：Form/List 导航、网络/文件权限隔离、插件热重载；Detail 详情块已支持第一版渲染。
- 默认插件进程每次查询或执行重新启动，先保证协议简单和运行时可替换。
- Manifest 可声明 `mode: "resident"` 使用常驻外部进程。当前已支持 `initialize`、`query` 和 `execute`；`index`、`update`、`cancel`、`shutdown`、超时恢复和增量索引生命周期仍属于后续工作。该模式是内嵌 Lua 之前的过渡方案。
- 内嵌 Lua 模式属于目标架构：Lua VM 由 wowie 自带，插件与 Launcher 共进程运行，不依赖用户安装脚本运行时。
- 增量索引协议需要额外定义 `revision/cursor`、`upsert/remove` 和 `progress/ready`，避免 Launcher 与具体数据库或第三方同步机制耦合。
- 插件不要直接绘制 Slint UI，所有展示应通过 Item 和统一 View Primitive 表达。
- 查询请求包含 `locale` 和 `fallback_locale`。插件应按 `locale → 语言基础码 → fallback_locale` 查找 `locales/*.json`，代码中只使用 message key。`locale=system` 时由插件运行时自行读取系统语言。

### 详情面板

插件可以为 Item 提供声明式 `detail`，Launcher 会在选中该结果时显示右侧详情面板。详情只能由受限的 View Primitive 组成：

```json
{
  "detail": {
    "title": "Repository",
    "subtitle": "facebook/react",
    "source": "GitHub",
    "blocks": [
      {"type": "icon", "glyph": "★", "color": "accent"},
      {"type": "text", "text": "A JavaScript library", "color": "secondary"},
      {"type": "separator"},
      {"type": "metric", "label": "Stars", "value": "230k", "color": "primary"}
    ]
  }
}
```

支持的块类型为 `text`、`metric`、`icon`、`weather` 和 `separator`。`separator` 当前只保留布局间距，不绘制可见分割线；详情面板按内容数量自动增高，不使用滚动页面。`weather` 的 `value` 使用 `clear`、`cloud`、`rain`、`snow` 或 `storm`，用于绘制内置天气图形。颜色只接受 `primary`、`secondary`、`accent` 等语义值；插件不能传入 Slint 代码、任意控件或窗口句柄。

Launcher 最多渲染 10 个详情块和 3 个详情操作；超出部分会被忽略，以保证插件不能无限扩大窗口。详情操作必须同时在 Item 的 `actions` 中声明对应的 action id，点击后由插件的 `execute` 方法处理。
