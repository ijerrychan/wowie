# 优化待办

本文记录当前代码整理后仍未实现的优化项。已完成的配置原子写入、后台图标与详情图片加载、动作和 session 异步化、结果快照、分页去重、图像预算、排序一致性及 Windows 目录指纹优化不再重复列入。

优先级含义：

- **P0**：可能造成资源失控、数据丢失或系统集成行为错误，应优先处理。
- **P1**：明显影响性能、响应时间或长期运行稳定性。
- **P2**：维护性、可测试性和低频场景改进。

## P0：正确性与资源边界

- [x] **限制 ShellLink 文件读取并补齐损坏文件测试**（`src/platform/windows/shortcuts.rs`）。原生与回退路径都先拒绝超过 4 MiB 的文件，回退读取使用有界流并保留所有偏移/字符串边界检查；新增截断、ANSI、Unicode 和超大文件测试。验证：`cargo test --quiet`（2026-09-25）。

- [x] **让全局快捷键更新具备回滚语义**（`src/platform/windows.rs`）。更新值先做解析校验；新注册失败时恢复旧注册并记录冲突/恢复失败原因，避免配置刷新后快捷键静默失效。验证：`cargo test --quiet`、Windows 编译检查（2026-09-25）。

- [x] **统一后台任务调度与取消**（`src/utils/background.rs`、`src/ui/mod.rs`、`src/ui/details.rs`、`src/ui/results.rs`）。短生命周期 UI 任务统一进入 4 个 worker 和 128 个槽位的有界队列，队列满时拒绝新工作；取消 token 和查询/详情代次共同阻止过期任务继续处理或写回。长期监听线程仍保持独立生命周期。验证：`cargo test --quiet`（2026-09-25）。

- [x] **统一目录发现与指纹扫描的链接策略**（`src/providers/app/discovery.rs`、`src/utils/mod.rs`）。发现和指纹扫描共用 reparse/symbolic-link 判定；访问错误或路径消失时跳过该项，junction 不再递归或重复索引。验证：`cargo test --quiet`（2026-09-25）。

- [x] **为插件所有回调建立结构和内存上限**（`src/plugin.rs`、`docs/插件开发.md`）。初始化脚本/manifest、query/detail/execute/empty-state/icon 响应、storage JSON 均在转换为宿主模型前经过字节、深度、节点和字符串预算；结果、动作、详情块、表格和文本再按字段上限截断。验证：`cargo test --quiet`（2026-09-25）。

## P1：性能与长期运行稳定性

- [ ] **将历史记录持久化移出锁和 UI/搜索路径**（`src/core/ranking.rs`）。`save_locked` 目前在持有历史互斥锁时序列化并执行原子写入。改为快照后交给单独 writer 线程，合并短时间内的连续写入，避免磁盘抖动阻塞排序和启动操作；退出时等待最后一次写入完成。

- [ ] **为行为历史增加全局压缩策略**（`src/core/ranking.rs`）。当前只限制收藏和每个 engine 的搜索历史，`items`、`query_launches` 和 `query_last_used` 没有总量或过期清理。按最近使用时间和数量设置上限，加载旧版本时执行一次迁移/压缩，并覆盖空查询、大小写变化和大量随机查询的测试。

- [ ] **为 Steam 插件建立图标索引并支持缓存刷新**（`plugins/steam-games/main.lua`）。每个游戏发现阶段都会重复扫描 `librarycache`，缓存六小时内也无法感知安装、卸载和图标变化。初始化时建立 `appid -> icon` 索引；按库目录/VDF 指纹或可配置 TTL 触发增量刷新，并在刷新失败时保留上一份有效缓存。

- [ ] **减少插件 fuzzy match 的重复分配**（`src/plugin.rs`、Lua API）。`wowie.fuzzy_match` 每次调用都会创建匹配器和临时缓冲，Steam 等插件会对每个候选重复调用。提供批量匹配或可复用 matcher 的宿主 API，并比较大结果集下的分配次数和 P95 查询耗时。

- [ ] **改进自定义目录监视的扫描策略**（`src/providers/app.rs`、`src/providers/app/discovery.rs`）。当前仍以固定约两秒的递归指纹扫描作为变化检测。优先使用 Windows change notification，辅以去抖和定期完整对账；非 Windows 保留指纹回退。验证空闲期间 CPU 占用、深层目录变更延迟和大量文件目录的扫描耗时。

- [ ] **为平台监听线程增加统一停止信号**（`src/platform/windows.rs`、tray/hotkey/theme 监听）。快捷键、主题和托盘相关循环目前按线程生命周期运行，快捷键循环还使用固定 50ms 轮询。加入 shutdown token，退出时停止消息循环并释放注册、通道和托盘资源；用集成测试或诊断日志确认重复启动/退出不会残留线程。

- [ ] **合并 UI 中重复的搜索结果刷新流程**（`src/ui/mod.rs`、`src/ui/results.rs`）。查询变化、配置刷新和 provider 刷新仍有相似的“计算结果、更新模型、恢复选择、加载媒体”代码。抽取一个接收代次和共享快照的应用函数，统一空态、选择项和分页行为，减少后续修复只改到一条路径的风险。

## P2：架构、可测试性与基准

- [ ] **拆分过大的宿主模块**（`src/ui/mod.rs`、`src/plugin.rs`、`src/platform/windows.rs`）。按窗口生命周期、搜索协调、设置热加载、插件协议、Shell 集成和监听器拆分内部模块，保持现有公共边界不变；每个模块保留针对失败路径的单元测试。

- [ ] **建立可重复的性能基准**。覆盖启动索引、首次查询、连续快速查询、目录增量扫描、插件批量结果、图标缓存命中/未命中和历史写入。至少记录 P50/P95 延迟、峰值线程数、待处理任务数和缓存内存；将基准结果作为后续调度器和缓存改动的回归依据。

- [ ] **补充 Windows 系统集成回归矩阵**。覆盖快捷键冲突及更新失败、DPI/多显示器定位、主题变化、托盘退出、junction/符号链接、损坏 `.lnk`、不可读配置和 renderer fallback。把可自动化的样本放入测试夹具，其余形成手工检查清单。

- [ ] **按测量结果优化图标缓存淘汰和失败缓存**（`src/services/icon_service.rs`）。现有容量上限和负面结果处理已能限制增长，但远程图标没有统一 TTL，LRU 更新仍可能线性移动。只有在基准确认命中率或锁竞争受影响后，再引入远程过期策略或 O(1) 淘汰结构，并记录命中率、淘汰数和失败重试次数。

## 完成条件

每个条目完成后应同时更新实现、相关文档和测试/基准记录，并至少运行：

```text
cargo test --quiet
cargo fmt --check
cargo clippy --all-targets -- -D warnings
```

涉及 Windows 行为时，还要在真实 Windows 环境完成对应的系统集成回归。完成条目后将本文件中的复选框改为 `[x]`，并在条目中补充验证日期或测试名称。
