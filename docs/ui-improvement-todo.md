# UI 改进 TODO

## 当前实施状态（2026-09-21）

已完成：预览模型 v2 的结构化 DetailBlock、异步预览过期结果丢弃、加载/错误状态、插件结构化预览；操作面板的分组、快捷键、键盘循环导航和鼠标补充操作；全局列表/网格视图切换、自动列数和统一结果选择行为；窗口锚点的 Slint 布局计算、内缩诊断值与平台坐标缩放转换测试；shortcut session 的 execute/search/panel 入口状态、专属页头和返回导航。

已放弃：上下文菜单内的操作搜索框和过滤逻辑。操作面板保持轻量，直接使用分组、快捷键和键盘导航。

## 目标

在保持原生、轻量、键盘优先和跨平台可维护性的前提下，完善启动器的预览、操作、结果展示和扩展能力。

当前 UI 已具备：

- Slint 原生启动器窗口与结果列表
- 键盘导航、上下文菜单和快捷操作
- 结果详情面板
- 文本、指标、图标、天气、分割线等详情内容
- 深色主题、强调色和插件结果

主要缺口：富文本和媒体预览能力有限，操作面板功能较少，插件管理和页面模型仍不完整。

## 产品决策

### WebView 不作为核心 UI

优先实现原生的富文本、图片、代码、表格和链接等详情块。WebView 仅作为后续可选能力，用于确实需要网页渲染的插件，且必须满足：

- 按平台和功能特性隔离实现，不能污染核心 UI
- Windows 上采用可选的 WebView2 适配器，并支持运行时缺失时降级到外部浏览器
- 默认限制导航来源，不暴露任意宿主对象，不加载不受信任的远程页面
- 延迟创建、可取消、可销毁，避免影响启动器启动速度和内存占用

## 架构约束

- `PlatformIntegration` 只处理系统动作、窗口坐标转换、激活和平台能力检测。
- UI 几何、布局常量、锚点和视觉间距统一由 Slint 负责。
- 插件协议使用与渲染框架无关的数据结构，不向核心层暴露 Slint 类型。
- 查询模型、结果模型、页面模型和视图状态分离。
- 所有异步预览、图标和缩略图任务使用请求代次或取消令牌，禁止旧结果覆盖新结果。
- 新增平台能力必须提供能力检测和降级路径。
- 不在 Rust 平台代码中复制 UI 间距、窗口内边距或提示栏高度等常量。

## 非目标

- 不在第一阶段引入完整的任意插件自定义 UI。
- 不将 WebView 作为默认结果渲染器。
- 不允许核心启动器无边界地加载远程网页。
- 不通过复制平台专用布局常量解决 UI 定位问题。
