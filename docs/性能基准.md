# 性能基准

仅在调查性能问题或比较优化前后结果时选择相关基准运行；这些 `#[ignore]` 项不属于日常正确性验证，也不要求每次修改全部重跑。正常开发按[必要测试流程](开发文档.md#必要测试流程)执行。

这些基准以固定合成数据测量主要路径，避免覆盖用户索引、历史记录或配置。使用同一台机器、同一 Rust 工具链和 debug 测试配置重复运行；每条命令启动独立测试进程。项目启用了 release LTO，release 测试会显著延长首次构建时间，但不会改变测试负载或测量方法。

```powershell
cargo test providers::app::tests::provider_index_and_directory_refresh_benchmark -- --ignored --nocapture --test-threads=1
cargo test core::search::tests::first_and_rapid_query_benchmark -- --ignored --nocapture --test-threads=1
cargo test plugin::tests::fuzzy_filter_benchmark -- --ignored --nocapture --test-threads=1
cargo test services::icon_service::tests::icon_cache_hit_miss_and_lru_benchmark -- --ignored --nocapture --test-threads=1
cargo test core::ranking::tests::history_writer_benchmark -- --ignored --nocapture --test-threads=1
cargo test utils::background::tests::bounded_queue_metrics_benchmark -- --ignored --nocapture --test-threads=1
```

每个基准会先创建固定样本，再报告 P50/P95 延迟。`process_peak_threads` 是运行期间采样到的进程线程数，包含采样线程；`pending_tasks` 与 `pending_peak` 是共享后台队列当前值和进程内峰值。图标的 `decoded_cache_bytes` / `source_cache_bytes` 只统计缓存数据载荷，不含 HashMap、键和分配器元数据。队列峰值是单进程累计值；单独运行每条命令可保持结果可比。

| 基准 | 固定样本 | 输出的主要数据 |
| --- | --- | --- |
| `provider_index_and_directory_refresh_benchmark` | 500 个 URL 快捷项；8 次初始索引；7 次新增文件后的来源重扫 | 启动索引和变化来源重扫的 P50/P95、线程峰值、队列值 |
| `first_and_rapid_query_benchmark` | 10,000 个索引结果；1 次首次查询；100 次连续查询 | 首次查询、快速查询 P50/P95、线程峰值、队列值 |
| `fuzzy_filter_benchmark` | 1,000 个候选项；比较逐字段 API 和批量 API，各 100 次查询 | Rust 分配次数和两种 API 的 P50/P95、线程峰值、队列值 |
| `icon_cache_hit_miss_and_lru_benchmark` | 500 次命中、20 次独立缓存未命中、800 项缓存的 2,000 次 LRU 命中 | 命中/未命中/LRU P50/P95、条目数、有效缓存字节、线程峰值和队列值 |
| `history_writer_benchmark` | 2,048 条行为记录；50 次快照排队并等待最后一次落盘 | 快照排队 P50/P95、flush 时间、文件字节和线程峰值 |
| `bounded_queue_metrics_benchmark` | 固定 4 个 worker 忙碌时提交 64 个任务 | 放行时排队数、进程待处理峰值、活跃 worker 峰值和线程峰值 |

## 本机基线

测量环境：Windows，debug 测试配置，记录日期：2026-09-29。数据用于同机回归比较，不代表其他硬件上的绝对性能。

| 基准 | P50 / P95 | 其他指标 |
| --- | --- | --- |
| 应用索引 / 来源重扫 | 启动 P50/P95 43.8/506.6 ms；重扫 61.1/86.3 ms | 500 个临时 URL 项；峰值线程 6；待处理任务 0 |
| 首次 / 连续查询 | 首次 61.6 ms；连续查询 P50/P95 202.7/295.0 ms | 10,000 项；100 次连续查询；峰值线程 6 |
| 插件批量匹配 | 单项 P50/P95 2.583/2.973 ms；批量 1.936/2.318 ms | 每查询 Rust 分配 3898 降至 8；峰值线程 6 |
| 图标命中 / 未命中 / LRU | 命中 P95 <1 μs；未命中 351/381 μs；LRU P95 优化前 41 μs、之后 <1 μs | 命中率 96.2%；32 次淘汰；失败重试 4 次、失败缓存 0 项；像素数据 2,304 B；满缓存 2,097,152 B |
| 历史快照 / flush | 排队 P50/P95 1.752/2.044 ms；flush 87 ms | 2,048 条；落盘 426,814 B；峰值线程 7 |
| 后台队列压力 | — | 4 个 worker 全忙时排队 64；峰值待处理 64；峰值活跃 worker 4；进程峰值线程 10 |

LRU 对照在 800 项 / 1.64 MiB 载荷上测量。访问更新改为追加访问序号，清理时跳过过期序号，并在队列长度超过 `2 × 活跃条目数 + 64` 时压缩；同负载的 P95 从 41 μs 降至小于 1 μs。图标失败项不进入缓存，5 次缺失资源解析触发 4 次重试，缓存中失败项仍为 0。
